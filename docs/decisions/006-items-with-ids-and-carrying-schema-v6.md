# ADR 006: Ground wood becomes first-class items, colonist carrying, schemaVersion 6

- **Status:** accepted
- **Date:** 2026-09-18
- **Scope:** simulation (`WorldState`, the toil executor), persistence (save
  schema and migration)
- **Implements:** [ADR 003](003-scheduling-explainability-save-integrity-mobile-first.md),
  principle 3 (save integrity is a named strategy); objective #189.

## Context

Objective #189 asks for ground wood to stop being a per-tile counter and
become a first-class item — `{id, x, y, kind, count}` — so a later haul job
(t5) and stockpile zones (t4) have something with an identity to reference
and reserve. This is a new persisted, public data shape: `game-state.schema.json`
and the save envelope both change, so per `AGENTS.md` ("update the relevant
contract, schema, example, test, and a short numbered ADR when the decision
crosses a boundary") the decision needs a numbered ADR, not just an
implementation.

## Decision

1. **Items replace the per-tile wood counter.** `WorldState._items` is a
   dictionary keyed by a unique item id, each value `{id, x, y, kind,
   count}`. `get_ground_wood(x, y) -> int` becomes a derived sum over items
   at that position with `kind == "wood"`, kept for existing callers/tests
   rather than removed, so no caller outside `WorldState` needs to know
   items exist yet.
2. **Ids are generated by a single monotonic counter.** `_next_item_id`
   hands out `"item_<n>"` ids, never reused. `state_hash()` includes
   `_next_item_id` alongside `_items`: two states with the same items but a
   different counter would otherwise hash identically while handing out
   different ids on the next chop, breaking deterministic state identity.
3. **The toil executor gains `pick_up`/`place`.** Per
   [`colonist-ai.md`](../architecture/colonist-ai.md) 3.3, `pick_up(colonist,
   item_id)` requires the colonist to be on or adjacent to the item's tile
   and the item to still be on the ground; it removes the item from the
   ground map and sets the colonist's `carrying` field. `place(colonist,
   cell)` requires the destination cell to still be free of any colonist or
   ground item; it moves the item to `cell` and clears `carrying`. Both fail
   with a typed rejection reason (`item_out_of_reach`, `item_not_found`,
   `destination_blocked`) rather than crashing when their precondition no
   longer holds by the time they run — the same "typed reason, never a
   crash" contract the rest of the toil vocabulary already follows.
4. **Colonists gain a `carrying` field.** `null` while nothing is held, or
   `{itemId, kind, count}` while carrying (no `x`/`y`: a carried item has no
   ground position). This is new persisted per-entity state, not derived.
5. **schemaVersion bumps 5 -> 6.** The persisted save drops the top-level
   `groundItems` array and gains `items: {nextId, list}` and each entity's
   `carrying` field.
6. **Explicit v5->v6 migration.** A version-5 save's `groundItems` entries
   (`{target: {x, y}, wood}`, a per-tile counter) become one first-class
   item per unit of wood, in `groundItems`' own tile-sorted order, with ids
   assigned sequentially (`item_1`, `item_2`, ...) so the scheme is stable
   (same input always yields the same ids) and non-colliding (every id used
   exactly once). `items.nextId` continues from the last id handed out so a
   migrated world never reuses an id on its next chop. Every entity gains
   `carrying: null` — a v5 save predates pick_up/place, so no item could
   ever have been carried, making `null` the truthful value rather than an
   inferred default. This follows the same explicit, chained, non-mutating
   migration pattern already used for v1->v5 in `save_migrations.gd`,
   restated in [`save-system.md`](../architecture/save-system.md).

## Alternatives considered

- **Keep the per-tile wood counter and add a parallel items table only for
  carried items.** Rejected: it would need two representations of the same
  concept (ground wood as a count, carried wood as an item) instead of one,
  and a later haul job (t5) or stockpile zone (t4) would still need ground
  wood to have an id to reserve — better to give it one now than migrate
  twice.
- **Let `pick_up`/`place` operate on stockpile zones now.** Rejected:
  objective #189 explicitly defers zone membership to t4; testing `place`
  against an arbitrary free tile keeps this change's scope to the item/toil
  mechanics alone.
- **Omit `_next_item_id` from `state_hash()`, since the item list itself is
  already covered.** Rejected during review: the counter determines the id
  of the *next* item a chop will create, which is state that diverges
  observably (a later save/load/chop sequence produces a different id) even
  when the current item list is identical, so it must be part of the hashed
  snapshot.

## Consequences

- `docs/architecture/contracts/game-state.schema.json`: `schemaVersion` const
  is `6`; `items` (`{nextId, list}`) and each entity's `carrying` field are
  new required shapes, replacing `groundItems`.
- `docs/architecture/save-system.md` documents `schemaVersion` 6, the
  `items`/`carrying` wire shapes, and the v5->v6 migration.
- `game/scripts/core/world_state.gd` gains `_items`/`_next_item_id`,
  `get_items()`, `_spawn_wood_item()`, and the `pick_up`/`place` support
  callables (`_item_lookup`, `_remove_ground_item`, `_place_ground_item`,
  `_is_cell_occupied`); `state_hash()` covers both `_items` and
  `_next_item_id`.
- `game/scripts/core/jobs/toil_executor.gd` gains `pick_up()`/`place()`.
- `game/scripts/core/persistence/save_migrations.gd` gains the v5->v6
  step; `test_save_migration.gd` gains a schemaVersion-5 fixture covering
  it.
- No stockpile zone, haul job kind, or viewer change is introduced by this
  ADR; they are explicitly deferred to tasks t4, t5, and t6.

## Acceptance criteria

- [x] `game-state.schema.json` requires `items`/`carrying` and fixes
      `schemaVersion` at `6`.
- [x] `save-system.md` documents schema version 6, the `items`/`carrying`
      fields, and the v5->v6 migration.
- [x] `save_migrations.gd` implements an explicit, non-mutating v5->v6 step
      converting `groundItems` into one item per unit of wood with a stable,
      non-colliding id scheme, exercised by a schemaVersion-5 fixture in
      `test_save_migration.gd`.
- [x] `ToilExecutor.pick_up()`/`place()` fail with a typed reason rather
      than crashing when their precondition no longer holds, covered by
      `test_items_pick_up_place.gd`.
- [x] `WorldState.state_hash()` covers `_next_item_id` as well as `_items`,
      covered by a regression in `test_items_pick_up_place.gd`.
