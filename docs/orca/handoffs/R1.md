# R1 handoff: extract `EventLog`

> **In short:** `game/scripts/core/world/event_log.gd` now owns the event list, the event
> sequence counter, the JobQueue event collector and the applied/rejected command envelopes.
> `WorldState` delegates. No behaviour change: a fixed scenario's save JSON, event log,
> command results and `state_hash()` are byte-identical before and after.

## Moved into `EventLog`

| From `WorldState` | To `EventLog` |
| --- | --- |
| `var _events` | `_events` |
| `var _event_sequence` | `_event_sequence` |
| `var _queue_event_sequence` | `_queue_event_sequence` |
| `_insert_event()` | `insert_event()` |
| `_next_sequence()` | `next_sequence()` |
| `_event_less()` | `_event_less()` |
| `_collect_queue_events()` | `collect_queue_events()` |
| `_applied()` | `applied()` |
| `_rejection()` | `rejection()` |
| `_pure_rejection()` | `pure_rejection()` |
| `_reject()` | `reject()` |
| `_apply_noop()` | `apply_noop()` |

- Bodies are verbatim. The only changes are the dropped leading `_` on methods that other
  objects now call, `_scheduler.queue` → the injected `_queue`, and `PRIORITY_COMMAND` → the
  injected `_command_priority`.
- `get_events()` stays on `WorldState` as a one-line delegation (same signature, same deep-copy
  output).
- Dependencies are explicit: `EventLog.new(clock: SeededClock, queue: JobQueue,
  command_priority: int)`. The module holds no reference to `WorldState`. It is created in
  `WorldState._init()` right after `_scheduler`, whose queue it collects from, and before the
  givers that receive its `Callable`s.
- Every call site in `WorldState` now calls `_event_log.*`. The `Callable`s handed to
  `CalendarAlertGiver`, `IncidentScheduler` and `CombatResolver` are now
  `_event_log.insert_event` / `_event_log.next_sequence`.

## Contract impact

- No schema bump, migration, ADR or contract change. `test_save_migration` fixtures are untouched.
- **Save format:** the keys `scheduling.eventSequence` and `scheduling.queueEventSequence` keep
  the same names, the same position in the `scheduling` literal and the same int values. The
  event list is still never persisted: `decode()` still restarts it empty.
- **`state_hash()` coverage for this module:**
  - Included: none. Before R1, `state_hash()` hashed none of these fields, and it still hashes
    none of them.
  - Deliberately excluded (unchanged): `_events`, `_event_sequence`, `_queue_event_sequence`.
    Because nothing is hashed, the module has no `hash_into()`.
- **Invariants from trimmed comments**, now in `EventLog`'s class doc:
  - the sort order of `_events`;
  - only the two counters are persisted;
  - the event log is not in `state_hash()`;
  - `pure_rejection()` never appends an event or draws a sequence number.

### Save JSON byte-identity

[`R1-scenario_dump.gd`](R1-scenario_dump.gd) runs one fixed scenario:

- seed 777, incidents enabled;
- every 25 ticks: random orders, previews, a bogus command type, a tick mismatch and an
  unknown `cancel_job`;
- `trader_visit` at tick 60, `wolf_attack` at tick 120 and a zone at tick 180;
- 400 ticks, then `SaveIO.write_atomic`, then `from_save_state`, then 300 more ticks, then a
  second save.

The script writes both saves, both event logs and every command result plus `state_hash()`.
Run it on `be93a02` and on the branch head, then compare the outputs:

```sh
godot --headless --path game --script "$PWD/docs/orca/handoffs/R1-scenario_dump.gd" -- "$OUT/before"   # on be93a02
godot --headless --path game --script "$PWD/docs/orca/handoffs/R1-scenario_dump.gd" -- "$OUT/after"    # on HEAD
for f in save_400 save_700 events_400 events_700 results; do cmp "$OUT/before/$f.json" "$OUT/after/$f.json" && echo "$f identical"; done
```

Result: all five files are identical. Both runs print
`scenario_dump: io1=true io2=true events=585/494 hash=2076234758/2152777962`.
