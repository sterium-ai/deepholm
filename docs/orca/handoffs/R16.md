## What changed in the core

**Comments.** The rule: each function keeps a *why* of at most three lines, and a class doc
says what the module owns plus its invariants. Removed: *how* narration the code already
says, history ("before R4", "extracted to stay under the line budget", old schema numbers),
and repeated essays. Every invariant the old prose stated survives as one line in the class or
function doc. Examples, all checkable in the diff:

- `JobQueue`: reservations exist only while a job is active; a site's footprint is reserved
  to `site:<id>` by `ConstructionSystem`, never to a job; `_pending_fail_reasons` is never
  persisted; backoff never moves a job's aging position.
- `EventLog`/`JobEventLog`: sort order, retention and the "nothing here is hashed" rule.
- `WorkProgress`: key format, at most one owner per key, and suspended entries are consumed,
  never inherited.
- `WorldGenerator`: fixed pass order, river carved last, and the outcrop substream never
  advances the shared RNG.
- `RescueGiver`/`NeedGiver`: tick order and restore order.
- `StateCodec`/`SaveCheck`: maps encoded in sorted-key order; a missing key is a migration
  error and an unexpected key a `schema_error`.

**Stale references.** Comments that named `WorldState._x`/`world._x` members moved by R1–R14 or
the A-tasks now name the owning module. The R1–R12 handoffs list these under "stale
references", for example `_insert_event` → `EventLog.insert_event()`, `_decay_needs()` →
`NeedsSystem.decay_needs()`, `world._object_health` → `ObjectTable.object_health` and
`_advance_colonists()` → `TickPipeline._advance_colonists()`. Every
`WorldState._x`/`world._x` still named in a core comment exists in `world_state.gd` today (16
names, checked). No core comment still says "core-budgets.json cap" or "line budget".

Two comments were wrong, not just stale, and were corrected:
- `relations.gd` claimed it was "not consulted by combat". Combat uses `relation()` with the
  runtime `factionId` (ADR 021).
- `command_checks.gd` listed a WorldState member `_faction_may_be_ordered` that does not
  exist. The list now names the modules it reads.

**Asserts (invariants that were prose).** Each is O(1) or O(owners), sits next to the code
that keeps the invariant, and cannot fire in normal play:

| File | Assert | Why it holds |
| --- | --- | --- |
| `jobs/job_event_log.gd` `append()` | `event.sequence == _first_sequence + _events.size()` | the class invariant. `JobQueue._emit()` is the only caller, `_sequence` starts at `_first_sequence` (`reset()` on restore) and goes up by 1 per append, and trimming moves `_first_sequence` in step |
| `jobs/toil_executor.gd` `pick_up()` | `moved > 0` before `add_to_hands` | the `moved <= 0` early return just above it. It pins "hands never hold a count-0 entry" (ADR 037) |
| `jobs/work_progress.gd` `restore_owners()` | every owner key is a live progress key | owners are only set for keys in `progress`, and progress keys are erased only when they have no owner |

**New test `test_core_invariants.gd`** (a public-API world: chop/mine/dig orders and a
stockpile, 300 ticks):
- `get_events()` is sorted by (tick, system_priority, entity_id, sequence), with unique
  sequences (the `EventLog` class doc).
- On every tick, hands hold at most one entry per kind, every count is ≥ 1, and the total is
  ≤ `HANDS_CAPACITY` (ADR 037, `Inventory` class doc).
- Events and the retired-job history are never persisted or hashed. A save/load round trip
  keeps `state_hash()`, re-encodes to the same save JSON, starts with an empty event log,
  stays hash-identical with the original for 20 more ticks, and never reuses an event
  sequence.

**Budgets** (`docs/architecture/core-budgets.json`): `toil_executor.gd` fell from 963 to 636
lines. `check_core_budgets.py` fails while an exception the code no longer needs is still
listed, so that exception is removed. `world_generator.gd`'s exception is lowered from 1178 to
870 (867 lines, rounded up to the next 10). Nothing was raised. The two stricter caps
(`job_queue.gd` 790, `global_assignment.gd` 688) are unchanged.

## Docs

- **`docs/architecture/*.md`**: every function or field these docs cite now resolves to a
  current definition, attributed to the module that owns it.
  - `orders-and-movement.md`: about 75 references fixed. Examples: `_load_work_ticks()` →
    `ContentTables.work_ticks()`, `_begin_reroute()` → `ToilExecutor._begin_go_to_reroute()`,
    `_spawn_wood_item()` → `ItemTable.spawn_item()`, and `_passable_for_worker()` →
    `Passability.passable_for_worker()`.
  - `foundation-audit.md`: 23 references fixed.
  - `colonist-ai.md`: 15 references fixed.
  - `extension-points.md`: 6 references fixed.
  - `foundation-for-breadth.md`: 3 references fixed, and the stale "schema-v18" wording is
    gone.
  - `save-system.md`: 1 reference fixed.
  - `map-experience.md`: 1 reference fixed (review round 1).

  `R16-docrefs.py` checks this over `docs/architecture/*.md` and the core READMEs. Since review
  round 1 it also checks every explicitly named owner: each `Class.fn()`/`Class._field` must
  be defined in that class's file, where a class is a `class_name` or a file's CamelCase name.
  Godot built-ins (`new()`, `tr()`, `randi()`, `JSON.parse_string()` and similar) are skipped.
  Its only remaining hits are four functions in the dated `foundation-audit.md` that are
  deliberately marked as replaced, each saying by which task (`_reachable_candidates_only` by
  A4, `_pop_min_index` and `_ordered_neighbors` by A3, `_is_building` by B2). That audit keeps its findings and numbers.
  Its header now says citations point at each function's current home.
- **Three doc statements the code proved wrong** (`orders-and-movement.md`). Behaviour did not
  change; the doc now matches it:
  1. Need-job reservations do not go through `_commit_need_job()`/`_finish_need_job()`
     (neither function exists). `NeedGiver._commit()` submits through
     `GlobalAssignment.submit()`; the scheduler reserves the job on activation and
     `release_all` releases it.
  2. An unreachable need job does not fail `blocked_source_unreachable`, a reason that does not
     exist in the core. It takes the ordinary first-leg path,
     `WorldState._resubmit_unreachable_job()`.
  3. "No other tile kinds … are produced by order completion" left out `till`
     (soil → plowed_soil) and `sow` (plowed_soil → planted, removes one `seed` item). Both are
     now listed as `jobs.json` `effects` (ADR 051).

  Also fixed: "schemaVersion 26" and the "saves written before construction sites existed"
  paragraph (ADR 049 reset the schema to v1).
- **Field names:** `git grep` finds no `_events`, `_items`, `_tiles` or `_objects` in
  `docs/architecture/`, `docs/decisions/README.md` or the core READMEs. The command and its
  remaining hits are under "Known limitations".
- **ADR index** (`docs/decisions/README.md`, new; `source-of-truth.yaml` points to it as
  `decisions.index`): one row per record, 001–054, and no number is used twice
  (`ls docs/decisions | cut -c1-3 | sort | uniq -d` prints nothing). It has a redirect table
  for both renumberings:
  - `2ff9481` (2026-09-30), 28 rows reconstructed from that commit's renames. Before it, 012,
    018, 020 and 027 were each used twice.
  - This task: A5 (`053-job-storage-retired-history.md`, PR #34) and A16
    (`053-scenarios-as-content.md`, PR #35) both took 053 on the same day. A16's record merged
    later, so it becomes **054**. Only the file name and the heading number changed. Its four
    references inside the owned paths are updated: `extension-points.md`,
    `foundation-audit.md`, `source-of-truth.yaml`, and the `content_registry.gd` (×2) and
    `scenario_builder.gd` doc comments.

  Every `[ADR NNN](…NNN-….md)` link under `docs/` and `game/scripts/` points to a file with the
  same number (checked).
