# A13 handoff: content packs, one registry per session, ordered roots, strict ids

> **In short:** `ContentRegistry` is now built from an ordered list of roots: the base
> `res://content/`, then pack roots. Each pack has a `pack.json` (`{id, version}`) and adds
> collection entries or overrides them by id, whole entry, under explicit rules (ADR 010
> Amendment 1). A duplicate id, in the base or in a pack, fails with `schema_violation` instead of
> silently overwriting. The validator now enforces `enum`. `WorldState` accepts the session
> registry, and `boot.gd` builds that registry once (`session_content()`). Persistence is **not**
> touched: the owner's coordination note says R14 owns `save_io`/`state_codec`/`save_migrations`.
> The three save-side goals (whitelists from the registry, packs recorded in saves, a typed
> error for a save whose pack is missing) are therefore **follow-ups, not done**. The real bundle
> loads unchanged.
> Suite on the branch head: `run_tests: all 103 test(s) PASS  [742s]` (`main` `63d3d5f`: 102
> test files, `run_tests: all 102 test(s) PASS  [676s]`; the one added here is
> `test_content_packs.gd`).

## Pack rules (ADR 010 Amendment 1)

- Pack root = a directory with `pack.json` plus any subset of the **collection** kinds. Each kind
  file is `{"<kind>": [new entries], "overrides": [replacement entries]}`, both lists optional.
  Schemas always come from the base schema dir.
- New entry: its id must not exist in any earlier root, and it is appended. Override: its id must
  exist in an earlier root, and the whole entry is replaced (no field merge, no removal). Roots
  apply in order, and a later root wins.
- `schema_violation`: an id twice in one root (base file, or a pack's lists, or one id in both
  lists); a new entry reusing an existing id; a pack file for `calendar`/`manifest`/`mapgen` or
  for a kind without a base schema; an unexpected top-level field; an entry failing the entry
  schema; an invalid `pack.json`; the same pack id in two roots.
- `dangling_reference`: an override of an unknown id. A pack that breaks a base cross-reference
  fails the same way a broken base would, because `_check_references()` runs on the merged
  bundle.
- `missing_file`: a pack root without `pack.json`, including a root that does not exist.

## Behaviour change (called out)

- **Duplicate ids in the base** now fail (`schema_violation`). The real bundle has none, so it
  loads unchanged (`test_content_packs` compares every kind and document with and without the
  empty pack list, and compares `state_hash()` of a world built either way).
- **`enum` is enforced.** `actors.schema.json`'s closed `components` enum now rejects an unknown
  component as `schema_violation`, before `_check_references()` (which typed it
  `dangling_reference`) runs. That is why `test_actor_table` check 2 changed its expected code.
  The test still asserts failure, the typed code, the file, and now the component name too. ADR
  012's sentence "the enum stays inert" is superseded by ADR 010 Amendment 1. I did not edit ADR
  012: it is outside the owned paths. The `enum` inside factions' schema-valued
  `additionalProperties` stays inert; `_check_references()` still enforces it, and
  `test_factions` is unchanged and passing.

## Known limitations

- **Persistence follow-ups (blocked by R14, owner's note):** (1) `SaveIO` validation still uses
  its own tile/job/need literals; (2) saves do not record `ContentRegistry.packs()`; (3) there is
  no typed error for a save whose pack is missing; (4) `StateCodec.content_version()`,
  `SaveIO` (`max_world_size`), `SaveMigrations` (a registry and a `CalendarService.new()` that
  reads `calendar.json` directly) and `StateCodec.decode()` (which builds a `WorldState`) still
  build their own registry instead of receiving the session one. A loaded game therefore runs on
  the base bundle even when boot has packs.
- **Viewer paths outside the owned list:** `viewer/debug_scenario.gd` and
  `viewer/new_game_setup.gd` still build a `WorldState`/registry without the session registry.
- `CONTENT_PACK_ROOTS` is a constant in `boot.gd`; choosing packs at run time (command line,
  settings) is not part of this task (a mod browser is a non-goal).
- `calendar_service.gd` keeps its file-reading constructor, because `save_migrations.gd` still
  calls `CalendarService.new()` with no arguments.
