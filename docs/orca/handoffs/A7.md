## Review round 1 (`.orca-review.md`, REQUEST_CHANGES)

- **Blocking: `world_disposer.gd` traversed outside objects through Callables** (an active
  command listener led into `CommandRecorder` and cleared its recording). Fixed: the disposer
  now walks only what the world owns, through Object variables and their containers, never
  through a Callable. Callable variables are still reset, which breaks the cycles and only
  detaches an outside listener. `WorldState.dispose()` also leaves out the `WorldSetup` it was
  given, as well as the session `ContentRegistry`. New `test_world_dispose.gd`: a recorder
  hooked on the world keeps its commands, initial state and checkpoints after `dispose()`; the
  registry and setup are unchanged and a world rebuilt on them hashes as before; a disposed,
  dropped world is freed. The leak check stays at delta 0 (bench below).
- **Blocking: the packed tile cap trusted unvalidated dimensions** (a correctly hashed
  1,000,000 x 1,000,000 map with one run of 10^12 tiles would be expanded before
  `MapValidator` rejected it). Fixed: `SaveWire.unpack()` takes the session's `max_world_size`
  (`SaveIO.content_rules()`) and refuses a larger packed map with `MapValidator`'s own
  message ("map dimensions exceed the supported maximum", `schema_error`) before expanding
  anything; runs are then capped at width x height. New `test_save_wire.gd`: correctly
  rehashed saves (integrity over the exact text, as SaveIO writes) with the oversized map
  (refused in well under 2 s), a run longer than the map, a palette index out of range, an
  odd `tileRuns`, `tiles` next to `tileRuns`, a short record-table row, a repeated table key
  and a packed route whose bits do not match its box: each is a `schema_error`; the unchanged
  state rehashed the same way still loads.
- **Non-blocking: results author-reported** (the reviewer's sandbox could not run the save
  tests or fetch). The commands are under "Validation"; this round's suite line is quoted
  there.

## What changed

- **Saved route costs (the exact continuation).** `RouteSearch.snapshot()` adds `cost` (tile ->
  accumulated cost `g` of every visited tile). `restore()` uses it as saved; `_rebuild_costs()`
  now runs only for a state without `cost` (a v4 save or older). `SchedulingCodec` writes `cost` as an
  array in `visited` order (optional in `SchedulingValidator._valid_route_state()`: one finite,
  non-negative number per visited tile). `state_hash()` covers it through the snapshot.
- **Wire encoding (`persistence/save_wire.gd`, new).** `SaveIO` packs the plain state right
  before its one `JSON.stringify` and unpacks it right after the parse (after the int coercion,
  before migration and validation), so `StateCodec`, the validators, `game-state.schema.json`
  and every `test_save_*` that builds a plain state by hand see the same shape as before.
  - `map.tiles` -> `palette` + `tileRuns` (`[paletteIndex, runLength, ...]`).
  - Route searches (`entities[].route.rerouting`, `scheduling.pending.*.route`) -> `box`,
    `visitedBits` (bitset over the visited box), `cameFromDirs` (2 bits per visited tile),
    `costBytes` (float64 per visited tile), `frontierTiles` (int32 tile indices, frontier
    order), all base64. The bitset covers the box around the visited tiles, not the whole
    map: a whole-map bitset is 8 KB per search on 256x256, larger than the short A* searches.
  - `entities`, `jobs`, `scheduling.waiting` -> a record table (`{"$keys": [...]}` + one row per
    record). Tiles and routes alone left the 1,000-actor file at 62% of baseline (871 KB): the
    remaining bulk is per-record key names (`entities` 465 KB). The tables change the encoding
    only, never what is saved (non-goal respected), and bring it to 41%.
  - The packer leaves what it cannot restore exactly in the plain form (fewer than two
    records, a record with other keys, a hand-built route whose `cameFrom` is not one adjacent
    parent per visited tile, a tile off the map); the reader accepts the plain form of every
    packed field. Costs never appear as JSON numbers, so `_coerce_ints()` cannot touch them.
- **One pass.** `write_atomic()`: validate the plain state (unchanged), `SaveIO.state_text()`
  (pack + the one stringify), then `SaveIO.commit_body()`: one SHA-256 of that text, the
  envelope built around it, temp write, read-back through `read()`'s checks, rename. Before:
  three stringifies and a parse. `read()` hashes the raw `state` span
  (`SaveJsonInts._locate_state_object()` now also returns it) and falls back to the pre-A7 rule
  for older files and for tests that rehash an edited state.
- **Off the main thread.** `SaveIO.begin_write()` runs pack + stringify on the caller and starts a
  `SaveWrite` (`persistence/save_write.gd`, new) `Thread` running `commit_body()` with only the
  text, the path and `SaveIO.content_check()` (plain copies of the registry's version, packs and
  whitelists). The thread never sees the state Dictionary or the world. `SaveManager` runs one
  write at a time and waits for it before the next save or `load_best()`; the last-known-good
  pointer advances inside `wait()` on the caller's thread.
- **`WorldState.dispose()`** (`world/world_disposer.gd`, new): walks the objects the world owns
  (through Object variables and their containers, never through a Callable; review round 1),
  reading every variable first, then replaces each Object/Callable/Array/Dictionary variable
  of those objects with an empty one. The session `ContentRegistry` and the `WorldSetup` are
  neither walked nor reset, and containers are replaced, not cleared, so shared data survives. `world_state.gd`: +2 lines for `dispose()`, -5 by
  moving `_route_cost()`'s run-to-end loop into `RouteSearch.finish_steps()`.
- **Schema v5** (`StateCodec.SCHEMA_VERSION`), `SaveMigrations._v4_to_v5()` (shape unchanged;
  v4 routes stay without `cost`), fixture `game/scripts/tests/fixtures/save_schema_v5_fixture.json`
  written by `docs/orca/handoffs/A7-write-save.gd` (the R14/A5/A13b/A16b session; it prints
  `hash=1180613310`, the same as the earlier writers). 3,792 bytes against the v4 fixture's 8,827.

## Tests: what changed and why

- `test_save_*` "unchanged": every `test_save_*` check is kept and passes; the ones that build
  plain states, mutate them and expect a typed rejection run unchanged because the encoding
  is confined to the file. One file needed its version numbers moved, as A5, A13b and A16b did
  for theirs (the acceptance's own "version bump, migration and fixture" requires it):
  - `test_save_migration.gd`: the v1, v2 and v3 fixtures, and now A16b's v4 fixture too, must
    migrate exactly to the v5 fixture; the "current fixture loads and re-encodes unchanged"
    check moves from the v4 to the v5 fixture and also asserts that the file holds
    `palette`/`tileRuns` and no `tiles`. A16b's v3 -> v4 and `scenarioStart` checks are kept as
    they are (the latter now load the v4 fixture through the v4 -> v5 step too). Assertion sites
    159 -> 160.
- New `test_save_route_continuation.gd` (the acceptance test), two levels, each for both
  changes ("visited": a visited, non-start tile gets another cost while staying passable;
  "frontier": a frontier tile becomes impassable), applied between ticks after the search
  started and before the save:
  - Route level (40x40 grid, wall with gaps at both ends, 128 expansions before the change; the
    visited tile is the parent of the westmost frontier tile, 1 -> 12): `snapshot()` through
    `SchedulingCodec`, `SaveWire.pack_route()`, JSON text, `_coerce_floats_to_ints`,
    `unpack_route()`, `_valid_route_state()`, `_decode_route()`, `restore()`. The restored
    `snapshot()` equals the saved one exactly; the search finishes with the same status, path,
    expansions and resume() calls as the uninterrupted search.
  - World level (floor world, rock row with its gap at the east edge, chop order below it; a
    chair (move_cost 3) on a visited tile / a wooden wall on a frontier tile, through
    `ObjectTable.set_object()`): real `SaveIO.write_atomic()`/`read()` and `StateCodec.decode()`;
    `state_hash()` equals the uninterrupted world's before the first tick and after every
    tick, the search ends with the same status, path and expansion count, and the worlds stay in
    step 30 ticks later.
  - Negative control in every case: the same save restored without `cost` (today's
    `_rebuild_costs()`) must diverge: a different result at route level, a different
    `state_hash()` at world level. All four controls diverge, so the test fails on the old
    restore.

## Known limitations

- `boot.gd` and `viewer/autosave_trigger.gd` still call the blocking `save_manual()`/
  `save_autosave()`, so the game does not yet benefit from the thread, and `boot.gd` does not
  call `dispose()` on a replaced world. Both are one-line changes outside the owned paths;
  follow-up for the owner (A9 has landed, so `boot.gd` is free).
- A loaded search's visited tiles come back in row-major order instead of discovery order.
  Nothing reads that order (`state_hash()` stringifies with sorted keys, and Godot's Dictionary
  `==` ignores order); `test_save_route_continuation.gd` checks `snapshot()` equality.
- One save write per `SaveManager` at a time (a second `begin_*()` waits for the first).
