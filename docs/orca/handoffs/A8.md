# A8 handoff: A* and region-aware routing

> **In short:** `RouteSearch` is now an A* search (heuristic Manhattan × minimum tile cost, 1 for
> every map the content allows). It still returns a cheapest path. On the generated map at
> distance 256 it takes 266 expansions in 5 ticks of route budget, against Dijkstra's 15,462 in
> 242 (acceptance: ≤ 1,500 and ≤ 25). Every caller that starts a search now passes the colony
> region check, so a target in another region is refused before any expansion. ADR 054 fixes
> the new tie-break (lowest f, then lowest h, then latest pushed) and accepts that equal-cost
> paths may differ. The save format is unchanged. Fourteen existing test files change (13 failed
> on the first full run; `test_route_search_recorded` was updated before it could): they pinned
> Dijkstra's expansion counts, its tie-break, or a search that took several ticks. Each gets the
> smallest change that restores its premise and quotes ADR 054 (list below).
> Suite: `run_tests: all 119 test(s) PASS  [659s]`.

## Contract impact

- **ADR 054** (new): A*, the (f, h, latest insertion) tie-break, cost improvement, the
  found-on-discovery optimality proof, Dijkstra mode (`min_cost = 0`), the region check in the
  constructor, and the accepted consequence that equal-cost paths may differ.
- `routing/README.md` and `orders-and-movement.md` updated as above.
- **Save format: unchanged, no schema bump.** `snapshot()` has the same keys and value shapes
  (`frontier` = open tiles in insertion order, `visited` = discovered tiles, `came_from` = best
  parent). A Dijkstra search saved by an older build is a valid A* state and continues to a
  cheapest path. In-flight search *contents* differ from `main` for the same scenario, and so do
  `state_hash()` values that include them; that is the accepted path change, not a format
  change.

## Tests changed and why

Four reasons, all consequences of ADR 054:

- **(P) pinned Dijkstra values or tie-break** — the test recorded expansions/paths or the
  row-major tie-break.
- **(M) "multi-tick search" premise** — the scenario needs a route search still in flight after
  N ticks; A* resolves an open-floor route in about one expansion per tile of distance, so the
  fixture adds an obstacle (or a shorter wait) that makes the search last again.
- **(R) region check** — the scenario relied on a search toward a walled-off target running.
- **(E) equal-cost path** — the scenario relied on Dijkstra's choice between two equally cheap
  paths.

## Review round 1

Codex: `REQUEST_CHANGES`, one blocking and one non-blocking finding.

- **Blocking — `global_assignment.gd:663`, `_resolve_path()` starts a fresh search during save
  restoration without a region check.** Correct: `restore_scheduling()` re-runs every pending
  "found" pair's search to completion with no step budget, so a target walled off after it was
  found and before the save made a load sweep the whole map synchronously. Fixed as described
  in the file table: the region check now reaches `_resolve_path()` from `StateCodec`. The path
  it restores is the same as before (empty for such a target, the old search also ended
  unreachable); only the sweep is gone. Regression test
  `test_route_astar.gd::_check_restore_refuses_found_pair_cut_off_before_save()`: a colonist's
  batch holds a "found" near pair and an in-flight far search, the near target is walled in,
  the world is saved, and `restore_scheduling()` is run on the decoded state with a counting
  cost callable. With the check: 194 cost calls (the in-flight far search's `restore()` rebuilding its costs and the start-tile checks; the refused re-run expands nothing); without: 4,702 (the test requires < 1,000
  and > 2,000), the restored path is empty both ways, and `from_save_state()` keeps
  `state_hash()`. Verified that the test fails when `_resolve_path()` drops the check
  (temporarily passing `Callable()`): `ERROR: with the region check the restore must not sweep
  the map (4702 cost calls, 4702 without)`.
- **Non-blocking — the reviewer could not repeat the full suite (read-only sandbox).** No change
  needed; the suite was re-run on the round-1 tree, line quoted under Validation.

While writing that test, a `SCRIPT ERROR` inside one check function (a typo, since fixed) still
let the file print `test_route_astar: PASS` and exit 0: GDScript aborts only the failing function.
That is how every test in the suite behaves today, outside A8's scope; noted for the owner.

## Known limitations

- `docs/architecture/warnings-baseline.txt` could be lowered (`check_core_warnings` reports the
  count below baseline). It is outside A8's owned paths, so it is left for the owner.
- `bench_route_search`'s unreachable case constructs `RouteSearch` without the region check, so
  it still sweeps the whole open grid; the simulation callers never do.
- The region map follows the colony's passability. That is a superset of every faction's today
  (factions differ only at doors and the colony may pass them). A future faction that can cross
  something the colony cannot would need its own region map before it may use this check.
- Paths chosen among equal-cost alternatives differ from `main` (ADR 054). A playtest may show
  colonists taking different but equally short routes.
