# F6b-1 handoff: wild species, animal actors and population dynamics

> **In short:** six wild species live in `game/content/species.json`, with its schema. Animals
> are actors of kind `"animal"`: rows of the **shared actor table** (the same `_colonists` list
> and `ActorIndex` as colonists and raiders), created by `ActorTable.spawn_animal()`. Shipped
> `mapgen.json` seeds 26 of them through `WorldState.new()` from the world seed. A new
> TickPipeline phase, `"fauna"`, runs right after `"farming"`, surface only, and draws from its
> own salted RNG stream. Births are logistic (`1 − count / cap`). Saves move to schema v14:
> animals are saved as entities, and a new optional top-level `fauna` field holds
> `{nextAnimalId, rng}`, with a migration and a fixture. Bad species content is a fatal typed
> startup error. The viewer draws the wolf with the B3 pack art and the other species as coloured
> dots. `world_state.gd` stays at 767 lines. A14 (1000 colonists + 200 animals): a mean of about 106 ms
> per tick against about 96 ms with no animals (within the 167 ms ×3 budget); the fauna phase
> alone costs about 0.72 ms. The other ~9 ms is the shared table being walked by the other phases.
> Design and decisions: ADR 070.
>
> **Review round 1** (Codex, REQUEST_CHANGES with 5 blocking findings). All five are now fixed
> in code with tests. Findings 2 and 3 follow the owner's round-1 decisions (quoted below): the
> separate roster is gone, and shipped mapgen seeds animals.
>
> **Review round 2** (Codex, REQUEST_CHANGES with 3 blocking findings). The two save-validation
> findings are fixed in code with tests. The manifest finding is recorded as an exception that
> needs owner approval (see *Pending owner decisions*). The three non-blocking findings are
> addressed (the report claims are corrected, and the mixed-diet test now exists).
>
> **Review round 3** (Codex, REQUEST_CHANGES with 3 blocking findings). Animal-only fields on
> other kinds are now refused, and the B7 pack generator now knows the animal placeholder; both
> come with tests. The manifest reference is now implemented, per the owner's round-3 decision
> (BACKLOG on main, commit `e9292ad`: no exception). `manifest.json` lists `species.json` and every
> other content file in a new `content` array, and the registry refuses a bad entry; with tests.

## Contract impact

- Save schema **13 → 14**, shipped with:
  - the migration (`save_migrations.gd`: it adds nothing, because an absent field means no
    animals);
  - the validators (`FaunaValidator`, and `EntityValidator` for animal entities). A save with
    animal entities needs `fauna`, with `nextAnimalId` above every `animal_<n>`. Animal ids
    match `^animal_[0-9]+$`, and animals are at `z = 0`. Other kinds may not carry the
    animal fields;
  - the fixture (`save_schema_v14_fixture.json`);
  - the contract (`game-state.schema.json`).
- Animals are entities with `kind: "animal"` and the fields `species`, `bornTick`,
  `lastMealTick` and `nextBirthTick`. The new optional top-level field is
  `fauna: {nextAnimalId, rng: {seed, state}}`.
- `state_hash()`: animals hash as entities. `FaunaSystem.hash_into()` adds the fauna block only
  once an animal has ever spawned (`nextAnimalId > 0`).
- With shipped content every new world now seeds 26 animals, so pinned hashes of default worlds
  change (see *Knock-on edits*).
- Content manifest: `manifest.schema.json` gains an optional `content` list of file names, and
  the registry refuses an entry naming a missing file, the manifest or a duplicate (owner
  decision `e9292ad`). Other packs and fixtures without the field are unaffected.
- New content kind: `species.json` with its schema, listed in `manifest.json`. `mapgen.json` gains `animal_counts`, and
  `actors.json` gains the `"animal"` kind.
- View snapshot: a new `animals` list (a deep copy).
- ADR 070 added.

## Acceptance → evidence

Each criterion is exercised through real ticks (`WorldState.tick()`), not internal calls:
1. **20 grasshoppers, no predators, reach the cap and hold it.** `test_fauna_population.gd`:
   the count reaches 60 and stays at 60 over the following window.
2. **20 grasshoppers plus 2 birds stay below the cap, and the birds survive.**
   `test_fauna_population.gd`: the grasshopper peak is under 60, and birds are alive at the
   end.
3. **A wolf with no prey dies within its starvation window.** `test_fauna_population.gd`: the
   wolf is alive at `starve_ticks − 10` and gone at `starve_ticks + 10`.
4. **200 animals with 1000 colonists keep the A14 budget.** `F6b-1-bench.gd`, with animals in
   the shared actor table:

   | Run (256×256, seed 42, 1000 colonists, 60 ticks) | Mean | p95 | Max |
   |---|---|---|---|
   | Branch head, 0 animals (run 1 / run 2) | 97.32 / 95.59 ms | 116.27 / 116.28 ms | 116.42 / 117.81 ms |
   | Branch head, 26 shipped animals (run 1 / run 2) | 94.12 / 96.35 ms | 109.73 / 110.93 ms | 111.41 / 117.95 ms |
   | Branch head, 200 animals, 200 alive at end (run 1 / run 2) | 105.93 / 106.70 ms | 125.05 / 126.91 ms | 126.74 / 128.97 ms |
   | Previous head (separate roster), 0 animals | 75.77 ms | 81.54 ms | 100.47 ms |
   | Previous head (separate roster), 200 animals | 74.74 ms | 78.16 ms | 81.62 ms |
   | Reviewer (separate roster), 0 / 200 animals | 79.63 / 85.29 ms | | |

   - The `"fauna"` phase alone averages 0.705 / 0.724 ms per tick with 200 animals (0.325 ms
     with the separate roster).
   - **Verdict: A14 holds, and the cost of the shared table is cited.**
     - 200 animals add about 10 ms to the mean (about 11%). Only about 0.7 ms of that is the
       fauna phase. The rest comes from the other phases (needs, labour, routing, the index…)
       walking a table that is 20% longer and skipping the animal rows by component; it is not
       attributed per phase.
     - Every run stays within the 167 ms ×3 budget (foundation-audit §1). None is under the
       16 ms one-frame figure, but that was already true with no animals.
     - The previous-head rows are from another machine state and are kept only for reference. The
       0-animal baseline itself moved from about 76 ms to about 96 ms between sessions, so compare
       rows within one session only.
   - **Bench fix:** `BenchCommon.world_with_colonists()` replaces the whole actor table, which
     now also wiped the mapgen-seeded animals. The bench re-spawns the shipped animals from a

## Known limitations and risks

- **Occupancy.** Animals are actors on tiles, so `_colonist_at()` and the cell-occupied checks
  now see them. A build or drop on an animal's tile is refused like one on a colonist. Animals
  move every few ticks, so the block is short. F6b-3 or the owner may want animals to be
  ignored for building.
- **Combat.** Raiders and colonists do not target animals yet: combat is keyed on the combat
  component, which the `"animal"` kind lacks. F6b-3 adds hunting and animal combat on these
  rows.
- `world_state.gd` stays at 767 lines by putting the new wiring on existing lines (the
  `FaunaSystem.new(...)` call carries a continuation line). Growing the file by about 3 lines
  would read better.
- `health` (on the entity, persisted) and `attack` (content only, from `species.json` through
  `FaunaSpecies`; not on the entity) are not used yet (F6b-3).
- Animals never path-find. A hungry predator takes one greedy step toward the nearest prey in
  sight; other animals wander.
