# B8 handoff: wall / workbench placement no longer lags

> **In short:** each mouse move with the wall or a build tool used to run one exact
> `WorldState.preview()` pass. For an impassable kind (wall, workbench…) that pass runs
> `ConstructionSystem._would_enclose_tiles`, a whole-map flood fill per colonist, which
> costs ~180–290 ms on a 200×200 map. It also ran again on every tick. Now a mouse move only
> lays out the hovered footprint or dragged rectangle. The exact check runs once, after the
> cursor has rested for 80 ms. A mouse move went from **~180–240 ms to 3–21 µs on average
> (worst 82 µs)** on 200×200, well under the 2 ms budget. The work is viewer only, with no
> simulation change.

## What changed

- **Deferred exact preview** (`map_view.gd`, on only for wall/build tools):
  - A hovered-tile change or a tick rebuilds `_list_tiles` only, and marks the preview pending.
  - `_process()` runs `preview_validity` once `PREVIEW_SETTLE_MSEC` (80 ms) have passed with
    no new tile.
  - Tiles not yet checked draw light grey. Checked tiles draw green, or red with an X, as before.
- **Ticks while the cursor rests.** If the tiles are the same, the last exact result stays
  on screen. A recheck is scheduled only if the world's tile change log
  (`get_dirty_cells_since`) or designation log (`get_designation_changes`) advanced since
  the last check, and at most once every `PREVIEW_RECHECK_MSEC` (1 s). Running the game
  therefore does not cause a periodic ~200 ms hitch.
- **A kind or orientation change rechecks at once.** `set_build_kind`,
  `set_build_rotatable` and `toggle_build_orientation` set `_preview_inputs_changed`. Over
  the same tiles, the exact check then runs synchronously, because the old result was for
  the old kind. This is a click, not a mouse move, so the old cost per click stays: the
  wall material picker turns a held rectangle from wood to stone straight away.
- **Commands are unchanged.** `OrderInput.apply()` still validates exactly on click and
  release. The preview is advisory, as for B1's coarse drag preview.
- **Draw culling.** `_draw` skips preview tiles outside the visible tile rect. This is the
  same rect `_drag_preview.draw` already used.
- **Other tools are unchanged.** For every other tool, `_preview_deferred` stays false and
  the previous synchronous path runs. `test_map_view_preview_cache.gd` still covers it
  unchanged.

## Tests

`game/scripts/tests/test_build_preview_budget.gd` covers wall hover, workbench hover and
wall drag 40×40 on 200×200. It drives the real entry points (`OrderInput.select_tool`,
`preview_validity` with `WorldState.preview`, `MapView._gui_input`) and checks four things:

- **Budget.** Each of 39 tile-changing moves costs < 2000 µs, timed best of 3 so a
  scheduler hiccup is not mistaken for the old ~180 ms flood fill.
- **The deferred result is exact.** After `finish_preview_work()`, `_preview_valid` equals a
  direct `orders.preview_validity(...)`, and the drag covers 1600 tiles.
- **A refresh with no world change** runs no check and keeps the exact result.
- **After a real accepted dig/mine order far away, then a tick:**
  - the tick, `refresh()` and `_process()` run no check synchronously;
  - the old result stays on screen;
  - `finish_preview_work()` then runs exactly one check.

`test_order_input.gd` (first full run, before the fix: `run_tests: 1 of 146 test(s) failed:
test_order_input`) caught a real bug: a material change over a held rectangle kept the old
kind's verdict. That is fixed above. The test gained one assertion and one flush; it lost none.

No test was removed or loosened. There are 145 `test_*.gd` files on `main` and 146 on the branch.

## Contract impact

- No change to commands, saves, schema or the simulation. Only the viewer changed.
- `MapView` has one new public method, `set_preview_deferred(enabled)`, called by
  `OrderInput.select_tool()`. `finish_preview_work()` (tests and benches) now also flushes
  the deferred check.
- For wall and build tools, a hover or drag move no longer leaves `_preview_valid` exact
  synchronously. Tests that read it must call `finish_preview_work()` first, as
  `test_order_input.gd` now does.

## Known limitations

- **The exact check still costs ~200–340 ms, once.** It runs in one frame after the cursor
  rests for 80 ms (or after a world change, at most once a second). That is one dropped
  frame at rest instead of one on every move. Making it cheaper means changing
  `ConstructionSystem._would_enclose_tiles` (core), which B8 may not touch.
- **Colonist movement alone does not trigger a recheck while the cursor rests.** The
  enclosure verdict also depends on colonist positions, so a resting preview can be stale
  until the next mouse move or world change. `apply()` still checks exactly, so a command
  is never wrongly accepted.
- **Owner confirmation is pending:** "no visible stutter" in the native playtest
  (`tools/play.cmd`).
