## Scope decision (asked in the terminal, answered by the owner)

The acceptance asks for "no core file above 800". Six files outside R12's scope were
already above that: `save_io.gd` 2287, `save_migrations.gd` 1532 and `state_codec.gd` 1409
(R14 shrinks them), `world_generator.gd` 1178, `toil_executor.gd` 960 (963 after A4)
and `content_registry.gd` 826. Five functions were above 80. I asked how to resolve this,
and the owner chose **"flat rule plus exceptions"**: the rule applies to every core file,
those six files and five functions are listed as exceptions frozen at their current size,
each with the task that removes it, and everything R12 touches meets the rule. I did not
touch those files.

The owner's coordination note (A4 and A6 in flight) asked me to stay strictly inside
`REFACTOR-PLAN.md` R12. I did not touch `combat_system.gd`, `toil_executor.gd`,
`trench_system.gd`, `state_codec.gd`, `event_log.gd`, `tile_grid.gd` or the viewer. Once A4
had merged, round 2 removed one dead function from `needs_system.gd` (A4's file until then).

`_rescue_candidates` (listed for R12 in the plan) had already moved in R6.

**Why world seeding and content tables moved.** With only the plan's list moved,
`world_state.gd` was still 869 lines with almost no comments left. Both moves are
stateless helpers with no back-reference (static functions over passed-in values), outside
every file other tasks are changing, and they are what got the file under 800.

**Dead code removed:** `_needs_tool_by_kind` (written, never read; flagged in R11),
`REASON_BLOCKED_SOURCE_RESERVED` and `REASON_BLOCKED_SOURCE_UNREACHABLE` (no reader anywhere:
`NeedGiver` uses its own constant of the first), and `NeedsSystem._full_needs()` (no caller;
flagged in R8; removed in round 2, after A4 merged). `LABOUR_DEFAULT` looked unused at first, but
`test_work_table_panel.gd` reads it, so it stays.

**Phase order.** `TickPipeline.PHASES`: `caches_begin, area_orders, clock, needs_decay,
need_giver, haul_giver, construction_giver, combat, scheduler, site_fetch_resolve,
rescue_giver, incidents_activate, escapes_activate, advance_colonists, approach_giver,
dig_finds, refused_reservations, collect_queue_events, calendar_alerts, incidents_advance,
tick_event, caches_end`. This is exactly the old `tick()` order. `caches_begin`/`caches_end`
are A4's `ActorIndex`/`ItemTable` `begin_tick()`/`end_tick()` lines, which opened and
closed `tick()` on `main`. The backlog's
"needs → givers → scheduler → toils → combat → incidents → calendar → caches" is a coarse
description. Reordering to match it (combat runs *before* the scheduler today) would change
behaviour, so I did not reorder anything. The ordering rules that the long comments in
`tick()` used to explain are now invariants in the module's class doc.

**Things the pipeline reads live.** StateCodec.decode() reassigns `_colonists` and
`_calendar_alerts_fired`, and three test files replace `world._calendar`. The old `tick()` read all
three from the world every tick, so the pipeline receives them as Callables, not values. The
pipeline is built at the end of `_build_dimension_services()`, which decode() calls again,
so it never holds a stale NeedGiver, RescueGiver, ApproachGiver or IncidentScheduler.

**Comments.** Following plan rule 6, a comment keeps the *why* in 1–3 lines. Every invariant
an essay described still has a line: tick ordering in `TickPipeline`'s class doc;
`_finish_job` is the only finish path; `_actor_may_reserve_target` checks a trapped actor
first and exclusively; `_carrying_view` is never persisted or hashed; `_ensure_held_tool`
appends rather than rebuilds (hash key order); `_resolve_refused_reservations` is transient
and drained at both mutators; `_remove_colonist_by_id`'s is_death rule; the RNG salts stay
distinct. Single-statement getters and delegations now sit on one line, the form the file
already used for the ToilBindings delegations.
