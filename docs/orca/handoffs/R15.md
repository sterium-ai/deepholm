## What changed

   functions taking the `WorldState`, with one plain read or write each and fully typed (0 new
   analyzer warnings). It groups:
   - module getters (`tile_grid(w)`, `colonists(w)`, `scheduler(w)`, ...);
   - wrappers of the private `WorldState` methods the tests used (`find_colonist`, `get_job`,
     ...);
   - the second-level privates the tests read or set (`need_giver_pending`,
     `incident_random`, `queue_jobs`, `set_incident_last_processed_day`, ...);

## Decisions

The owner asked for a conservative approach. These are the calls made:

- **No line in `world_state.gd`.** `TestAccess` uses static functions that take the world, so
  the façade needs nothing.
- **REVIEW's "a core module never receives WorldState" rule does not hold for this file, by
  design (owner's option 2).**
  - It is a deliberate, test-only exception: `TestAccess` stores nothing and no simulation
    code may call it.
  - Rule 4 in `test_architecture_rules` enforces this, and the class doc says so.
  - No ADR was added: this is not a new toil, decision layer or extension point. If the
    reviewer thinks the test seam needs one, it is a one-paragraph ADR.
- **A5 is now merged.** Its new and changed tests (`test_job_history`, `test_save_migration`,
  ...) went through the same conversion. `TestAccess.get_job(w, id)` still wraps
  `WorldState._get_job`, which A5 kept.
- **A16 (still in flight: `ScenarioBuilder`).** `tests/support/scenarios.gd` is test-only and
  touches neither `ScenarioBuilder` nor `boot.gd`/`new_game_setup`. None of the files the
  owner's note lists as in flight were touched (`event_log.gd`, `handlers/*`,
  `trade_system.gd`, `tick_pipeline.gd`, `job_index`/`job_history`).
- **Dedupe scope.**
  - Only scenario builders were moved: identical, assertion-free, with three or more copies
    across the suite.
  - Helpers that contain assertions (`_command_ok`, `_assert_no_orphaned_reservations`, ...)
    stay local, because moving them would change the per-file assertion count.
  - File-system helpers (`_cleanup_dir`, 9 copies; `_cleanup_save_dir`, 6) are not scenario
    builders and stay local.
  - Near-duplicates whose text differs (for example `_find_job` in `test_farming_content` and
    `test_labour_priority_scheduling`) stay local.
- **Split grouping is by check name.** The rules are in "Verification" so the split can be
  reproduced.
- **Viewer private fields are out of scope.** About 360 accesses remain in 26 viewer and boot
  tests (`boot._map_view`, `panel._line_for`, `sprites._sprites`, ...). `TestAccess` lives in
  the core and must not depend on scenes, and `game/scripts/viewer/` is not in the owned
  paths. Suggested follow-up: a viewer-side test seam, as its own task.

## Known limitations

- Viewer and boot tests still read viewer private fields (about 360 sites, 26 files), as
  described under "Decisions".
- Three string literals in assertion messages still name private functions
  (`SaveIO._validate_state()`, `GlobalAssignment._pending`). They are message text, not
  accesses.
- Doc comments that describe core internals (`WorldState._finish_job()`, ...) were left as
  prose.
- The doc comments that sat on the deleted copies went with them. They described
  `_isolate_need`, `_jobs_of_kind` and `_build_world` per file. The two facts in them that the
  code does not show are kept in `support/scenarios.gd`'s doc of `isolate_need`:
  - `kind = ""` zeroes every rate;
  - each world owns its own need definitions, so the mutation never leaks between worlds.
- Suite timing is machine-dependent. The +2.6 % comparison comes from back-to-back runs before
  the rebase, while another agent's suite was also running. The rebased run shared the PC with
  two other suites.
