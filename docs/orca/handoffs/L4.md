# L4 handoff: the viewer draws one active layer

> **In short:** ADR 045 §7 (step L4), decisions in **ADR 069** (proposed, owner sign-off
> pending).
>
> - `MapView.active_layer` is viewer state only: switching it issues no command, is never saved
>   and `set_world()` resets it to the surface. PageUp/PageDown or the ▲/▼ buttons beside a
>   "z N" label in the control bar switch it.
> - Tiles, objects, colonists, other actors, designations, ground items, stockpile zones and
>   construction sites are drawn only on their own layer; stairs/ramps (content `link_up` /
>   `link_down`) get a small up/down triangle.
> - Every command the viewer builds carries the active layer as `payload.z`.
> - The only core change is one column, `z`, in the view snapshot. **No schema bump**, save
>   unchanged, `state_hash()` unchanged (switching layers is checked against it).
> - Suite: `run_tests: all 138 test(s) PASS  [975s]`

## Contract impact

- **Save format:** unchanged (no persisted field touched; no schema bump).
- **`state_hash()`:** unchanged; the active layer is not world state.
- **Core API:** `WorldState.get_view_snapshot()` gains a `z` column (additive; existing

## Known limitations

- **Link markers are not exercised with real content.** No content object declares `link_up` /
  `link_down` yet (only the schema has them), so the triangles are untested beyond
  `LayerSlice.link_markers()`; they will show up once stairs/ramps exist.
- Rooms stay surface-only (ADR 068 §8), so the room label is empty on deeper layers.
- A deep layer is drawn from a copy that is re-read when one of its cells is dirty
  (O(width × height) per dirtying tick, only while that layer is active).
- Whether the core accepts a command with `z > 0` is the core's rule; the viewer only fills
  the field.
