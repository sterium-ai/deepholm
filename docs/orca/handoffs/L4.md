# L4 handoff: the viewer draws one active layer

> **In short:** ADR 045 §7 (step L4), decisions in **ADR 069** (proposed, owner sign-off
> pending).
>
> - `MapView.active_layer` is viewer state only: switching it issues no command, is never saved
>   and `set_world()` resets it to the surface. PageUp/PageDown or the ▲/▼ buttons beside a
>   "z N" label in the control bar switch it.
> - Tiles, objects, colonists, other actors, designations, ground items, stockpile zones and
>   construction sites are drawn only on their own layer; stairs/ramps (content `link_up` /
>   `link_down`) get a small up/down triangle.
> - Every command the viewer builds carries the active layer as `payload.z`.
> - The only core change is one column, `z`, in the view snapshot. **No schema bump**, save
>   unchanged, `state_hash()` unchanged (switching layers is checked against it).
> - Suite: `run_tests: all 138 test(s) PASS  [872s]` (review round 3)

- **Save format:** unchanged (no persisted field touched; no schema bump).
- **`state_hash()`:** unchanged; the active layer is not world state.

  readers ignore it).
- **Commands:** unchanged shape; the viewer now fills `payload.z` with the active layer
  (0 on the surface, as before).

## Known limitations

- **Link markers are not exercised with real content.** No content object declares `link_up` /
  `link_down` yet (only the schema has them). The test injects a link kind into the slice and
  checks `link_markers()`; the drawn triangles themselves show up once stairs/ramps exist.
- **A layer switch takes 2–3 frames at the A9 scale.** It rebuilds the tile and object layers
  in full (no per-layer cache in v1; owner amendment `15211a7`). Measured, see Review round 3:
  about 20–22 ms to a rock layer and 23–27 ms back to the surface, within the owner's
  ≤ 50 ms budget (`c769a48`); the one-frame target belongs to the cached-reuse task L4b.
- Rooms stay surface-only (ADR 068 §8), so the room label is empty on deeper layers.
- The active layer (surface included, since round 2) is drawn from a tile copy that is
  re-read when one of its cells is dirty (O(width × height) per dirtying tick).
- Whether the core accepts a command with `z > 0` is the core's rule; the viewer only fills
  the field.

## Review round 2

Verdict REQUEST_CHANGES (`.orca-review.md`). Done:

- **Blocking: switch timings at the A9 scale.** New `bench_viewer_layer_switch.gd`: A9's
  world (128×128, seed 42, 1,000 actors, the boot scene) with a second layer added through the
  save (rock, a floor cell under every other colonist, those ~500 colonists moved down). It
  times 40 alternating `set_active_layer()` calls and the `boot._refresh()` after each:

  ```
  "$GODOT" --headless --path game --script res://scripts/tests/bench_viewer_layer_switch.gd
  ```

  | Switch (mean / p95) | to deep (z 1) | to surface (z 0) |
  | --- | --- | --- |
  | before (`c5ba5d2`) | 46.0 / 54.2 ms | 255.0 / 275.7 ms |
  | after (this commit) | 25–31 / 29–35 ms | 44 / 49–58 ms |

  Ranges are across runs on this machine (noisy). The surface was slow mainly from the soil
  shore lookup and a string hash per cell; those are now a padded mask and a cache. The rest
  is GDScript per cell in the full tile pass (a bare `set_cell()` loop over 16,384 cells is
  ~1 ms, the pass ~12 ms on rock and ~22–33 ms on the surface), so **the 16.7 ms budget is not
  met**: an amendment is requested under Pending approvals rather than adding the
  per-layer cache that `15211a7` deferred. `switch+refresh` is 112–148 ms, but `boot._refresh()`
  costs about the same without a switch here (headless UI refresh and snapshot), so it is not
  switch cost.
- Drawn output is unchanged: the per-cell checks in `test_viewer_active_layer.gd`,
  `test_map_view_incremental.gd` and `test_world_pack.gd` pass.
- **Non-blocking:** the commit list is corrected (four commits, above). Owner sign-off of
  ADR 069 is still pending. The full suite was re-run (Validation).
