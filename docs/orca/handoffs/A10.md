## How the gate works

Godot reports analyzer warnings only while a debugger is attached. A plain
`--headless --script` run compiles scripts silently, and so does `--check-only`. The tool
therefore runs the probe twice:

1. **Without `-d`.** Every core script must compile. The probe checks `can_instantiate()`,
   because `load()` returns the resource even when compilation fails. The tool also rejects any
   `SCRIPT ERROR` line. This pass has to come first: when a script error happens under `-d`, Godot
   stops at the interactive debugger prompt and waits for input. I hit this hang while testing
   (see the plant check below).
2. **With `-d`** (the local stdout debugger). Each `WARNING:` line is followed by
   `at: GDScript::reload (res://scripts/core/<file>:<line>)`. The tool counts those lines, sorted
   into five kinds by message text:
   - `untyped_declaration` ("has no static (return) type");
   - `unsafe_property_access`;
   - `unsafe_method_access` ("… is not present on the inferred type");
   - `unsafe_call_argument` ("requires the subtype");
   - `other`, which holds the warnings that were already on by default, such as unused parameter
     and integer division.

Safety checks:

- The probe must report exactly as many scripts as there are `.gd` files under `core/` (69).
- The probe declares one untyped variable, `_warning_canary`, on purpose. If its warning is
  missing, the tool fails: warnings were not reported at all, and a count of 0 would otherwise
  pass.

The gate compares **per kind** (and the total), not per file. A refactor that moves code between
files therefore does not trip it. Swapping one kind for another also fails: for example, fixing
an unsafe call while adding an untyped variable.

## Why `Variant` for the 107 declarations

`var x: Variant = expr` behaves the same as `var x = expr`: no conversion, and `null` is still
allowed. A concrete type such as `Dictionary` or `int` would make GDScript convert the value or
raise an error on `null`. Many of these sites read `dict.get(...)`, `JSON.parse_string(...)` or a
`Callable` result, and then test `is Dictionary` or `== null`. A concrete type there would be a
logic change, so I used `Variant` everywhere.

One site is the exception. `state_codec.gd:1215` reads `world._scheduler`, which is declared
`var _scheduler: AssignmentType` on `WorldState`. Untyped, the analyzer had inferred that type;
with `Variant` it would have lost it and added 10 unsafe warnings. Annotating the same static
type it already had, `WorldState.AssignmentType`, removes 3 warnings instead.

I compared the non-untyped warnings of `origin/main` and the branch, grouped by file and
message. The only difference is those 3 removed warnings in `state_codec.gd`
(`get_next_id`/`get_sequence`/`get_tick` on `Variant`). No warning was added.

The task named 102 declarations; `origin/main` has 107 (`grep -rnE "^\s*var [A-Za-z_0-9]+ = "
game/scripts/core`). All 107 are now typed, and the same grep finds 0.

Out of scope, left as they were:

- 11 untyped member declarations without an initializer (`var _content`, `var _relations`,
  `var _reservation_table`, `var _registry`). They are not `var x =`, and the right type for them
  (`ContentRegistry`, among others) would touch how tests inject stand-ins.
- 417 untyped `for` iterators.
- 142 untyped parameters and 39 untyped return types.

All of them stay in the baseline.

## Known limitations

- **The CI step has not run under `pwsh` 7 here.** Only Windows PowerShell 5.1 is installed on
  this machine. The script uses nothing specific to either version, and the existing lint step
  already runs a `.ps1` the same way, but the first CI run is the real check.
- **The gate parses Godot's English warning text** to sort warnings into kinds. A Godot upgrade
  that rewords a message could move counts between kinds, and the gate would then fail. The
  fix is to regenerate the baseline with `-Update` in the upgrade change. The header records the
  Godot version for that reason.
- **Per-file counts are not gated.** A file can gain warnings if another file loses the same
  number of the same kind. I chose this on purpose, so that `R*` moves do not need a baseline
  edit outside their owned paths.
- **The baseline is not lowered automatically.** After a change that removes warnings, the gate
  prints "below baseline; lower it with -Update in this change". Lowering it is up to the author.
