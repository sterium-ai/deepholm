# L3 handoff: vertical links, the region graph and link edges in RouteSearch

> **In short:** Packages 1 and 2 of ADR 045 §3–§4 (decisions in **ADR 068**, proposed).
>
> - `VerticalLinks` (`core/map/vertical_links.gd`, new) derives straight up/down links from two
>   new object content flags (ADR 045: z grows underground, so the upper tile z declares
>   `link_down` and the lower tile z + 1 `link_up`). Links are rebuilt from tiles and objects,
>   never saved: **no schema bump** (the save stays v12, F5b's, as on `main`), `state_hash()` unchanged.
> - `RegionMap` floods every layer, numbers regions layer by layer from layer 0 (a single-layer
>   map keeps every id) and joins regions through links into a graph: `component_of()`,
>   `reachable()` across layers; `same_region()` stays planar.
> - `RouteSearch.set_vertical_links()` adds link ends as neighbours (above, z − 1, before the
>   planar offsets; below, z + 1, after them) with the 3D Manhattan heuristic; A8's tie-break is unchanged and
>   without links the search is the A8 search byte for byte.
> - Package 3 (wiring the links into the simulation's callers, perf at 1000 colonists) is
>   **L3b**, as the owner's note asked.
> - Suite (on `5399153`): `run_tests: all 137 test(s) PASS  [921s]`
> - Single-layer dumps A2, A14, A16 and R10: byte-identical to `main` `5399153` (`diff -r`
>   empty, final hashes included).

## Tests (`test_vertical_links.gd`, hand-built two-layer map with a stair pair)

1. `_check_split_merge_and_stair_removal`: without the stair the two layers are separate
   components; adding it merges them; removing it (`on_tile_changed`) splits them again.
   Layer-0 region ids are the ids a single-layer map gives.
2. `_check_broken_link_ends_are_not_links`: a one-sided stair, flags declared the wrong way
   round (`link_up` above, `link_down` below) or a blocked end is no link; the top answers
   `has_link_down`, the bottom `has_link_up`, and neither the other way.
3. `_check_dig_target_counts_only_its_own_layer`: an impassable dig target is reachable
   through its orthogonal neighbours on its own layer, never through the tile above/below.
4. `_check_two_rescues_keep_their_own_progress`: two rescue jobs on the same layer-1 target,
   reachable across the stair, keep separate `work_progress` keys; `key_parts()` round-trips
   the layer, and terminating one rescue clears only its own progress.
5. `_check_route_crosses_the_stair`: the search goes down the stair on the cheapest path,
   works upwards too, and gives the same path when run twice.
6. `_check_restored_search_continues_the_same`: a snake of walls on layer 1 makes the search
   outlast one `resume()`; the test asserts `STATUS_SEARCHING` before `snapshot()`, restores
   into a fresh search, and checks that the restored and the continued searches end on the
   uninterrupted path and in the same final snapshot.
7. `_check_link_index_stays_sorted`: incremental inserts match a full build, removals keep the
   rest in order, the index is strictly ascending and every indexed link answers both queries.
8. `_check_planar_search_unchanged_by_links`: with an empty link set, the snapshot and path
   equal the planar search's.

`test_route_search_recorded.gd` (A3/A8 recorded searches) and `test_regions.gd` pass unchanged.

## Review round 1: response

The owner's decisions are on `main` in `f8b6aec` (BACKLOG.md L3 "Review round 1", and the
`docs/orca/README.md` rule that ADRs merge as `proposed`).

1. **Link flags reversed against ADR 045** (`vertical_links.gd`): fixed. z grows underground,
   so a link needs `link_down` on the upper tile z and `link_up` on the lower tile z + 1. The
   API is now `has_link_down(tile)` / `has_link_up(tile)`; RouteSearch tries the tile above
   (z − 1) before the planar offsets and the one below (z + 1) after them; the fixtures, the
   ADR (§2, §6) and the routing README follow. A new case checks that flags declared the wrong
   way round make no link.
2. **Edits outside the owned paths**: approved as L3's scope by the owner in `f8b6aec` (see
   "Scope extension" below).
3. **ADR 068 still proposed**: per `f8b6aec`, it merges as `proposed` with "owner sign-off
   pending", like ADR 063; not a review gate.
4. **Mid-search restore test restored a finished search**: fixed. The new
   `_check_restored_search_continues_the_same` uses a walled snake on layer 1, asserts
   `STATUS_SEARCHING` after one `resume()` before snapshotting, and compares the restored and
   the continued searches with the uninterrupted one (path and final snapshot).
5. **Graph rebuild scanned the whole tile array**: fixed. `VerticalLinks` keeps an ascending
   index of link upper ends, maintained in `on_tile_changed()` with bsearch + insert/remove;
   `RegionMap` builds the graph from `upper_indices()`, O(regions + links).
   `_check_link_index_stays_sorted` covers it.
6. Non-blocking: the commit id is the reviewed one (`311e3e5`, `cbfabd7` after the rebase onto `f8b6aec`); the dumps were rerun against `07cd384`.
