## Why there is no code change

- A4's numbers (`A4.md:367`, `regions=262.3ms`) were measured on `7abae43`. That is **before**
  `a1c447b` (A2: "row-run region build"), which landed afterwards as #28.
- A2 rewrote `RegionMap._build()`. It labels whole passable row runs found with
  `PackedByteArray.find()`, joins the runs that overlap between rows with a union-find, and
  numbers each set when its first run is met in row-major order. It also feeds that build a
  cached `Passability.passable_mask()`, so no callable runs per tile. The ids are the same as
  the old scan-order flood fill (`A2.md` §regions).
- The build is still lazy and still paid inside tick 1 (`regions_unbuilt_before_tick1=true`
  below), so the bench measures it. It is just no longer dominant: about 4 ms of 27 ms. The rest
  of tick 1 is A4's need-giver pass (`need_giver=25.76` ms in the first-tick phase split).
- Moving the build to an explicit point, or making it faster, would save at most about 4 ms
  of a tick that is already 73 ms under target. It would also add a diff for R16 to rebase
  over. So I made no code change.
