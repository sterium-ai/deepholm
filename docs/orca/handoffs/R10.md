# R10 handoff: `CommandRouter` and command handlers

> **In short:** `game/scripts/core/world/command_router.gd` (`CommandRouter`) now validates
> the command envelope, dispatches every command type to one handler per family under
> `game/scripts/core/commands/handlers/` (orders, construction, zones, actors, incidents) and
> builds the applied/rejected envelopes through `EventLog`. `WorldState.apply()` and
> `preview()` are three lines each (doc line, signature, delegation). The two pre-mutation
> checks that still lived in `WorldState` (`place_object`, `cancel_site`) moved into
> `commands/command_checks.gd`, which is again the single place for them. Behaviour is
> unchanged: a 3,600-command fuzzer over every command type and malformed envelope gives
> byte-identical results, previews, event log, per-tick trace and saved states against
> `main`, and so do the R5, R7, R8 and R9 probes. `world_state.gd` drops from 2356 to 2040
> lines (against `origin/main` at `358e321`).

`WorldState` keeps `preview(command)` and `apply(command)` as one-line delegations to
`_commands` (a `CommandRouterType`), built in `_init()` right after `AreaOrders` (which keeps
receiving `WorldState.apply` as its callable, unchanged). `_route_cost()` and
`_UNREACHABLE_ROUTE_COST`, which sat between the moved functions, are not command functions
(`ConstructionSystem` ranks sources with them) and stay.

**Move, not rewrite.** [`R10-move_check.py`](R10-move_check.py) takes each of the 16 moved
functions from the base's `world_state.gd`, applies the listed mechanical renames and
compares the statements (comment, blank and `func` lines dropped) with the body in its new
file; it also fails if an old name is still defined in `WorldState`. The renames are:

- the new names (`_validate_command(` → `validate_command(`, `_apply_job_command(` →
  `apply_job_command(`, …) and the router's handler receivers (`_orders.`, `_construction.`,
  `_zones.`, `_actors.`, `_incidents.`); in `preview()` the `ConstructionSystem` receiver is
  `_construction_system.`;
- `var check := CommandChecks.<rule>(self, command)` → `var check: Dictionary =
  _check.call(CommandChecks.<rule>, command)`, and `_check_<x>_command(payload)` /
  `(command["payload"])` → `_check.call(CommandChecks.check_<x>_command, command)` (GDScript
  cannot infer a type from `Callable.call()`, hence the explicit `Dictionary`);
- injected `Callable`s: `_drop_carried_haul_item`, `_finish_job`,
  `_resolve_giver_association`, `_resolve_refused_reservations`, `_terminate_haul_job_by_id`,
  `_find_colonist` (with `: Dictionary` on the two `var x :=` lines) → `.call(`;
  `_incidents.force_spawn(` → `_force_spawn.call(`;
- in the two `CommandChecks` functions, the `WorldState` members they read get a `world.`
  receiver (`_object_definitions`, `_object_table`, `_tile_grid`, `_colonist_at`,
  `get_object`, `get_tile`, `_construction`) and `TILE_TREE`/`TILE_WATER` become
  `WorldState.TILE_*`. Their only added statement is `var payload: Dictionary =
  command["payload"]` (they now take the command, like every other `CommandChecks` rule).

Result: `move_check: 16 function(s), 0 differ`, against `main` before the rebase and against
`origin/main` after it. The checker is not vacuous: with `cx <= x + width` in
`_fail_haul_jobs_targeting_removed_zone()` it reports `1 differ` (tried, then restored).

Every rejection reason and message string is therefore unchanged (they are inside the
compared statements); no test file changed, so the strings the tests grep for are the same
ones, and the fuzzer below compares every rejection Dictionary byte for byte.

**Dependencies (no back-reference).** Neither the router nor any handler stores or receives
`WorldState`. They get sibling modules that `StateCodec.decode()` restores in place and
never reassigns (`_clock`, `_event_log`, `_scheduler`, `_progress_table`, `_construction`,
`_area_orders`, `_tile_grid`, `_object_table`, `_zone_table`, `_trade`) and Callables:

- `check: (rule: Callable, command: Dictionary) -> Dictionary`, one lambda built in
  `_init()` as `rule.call(self, command)`. `CommandChecks` rules are static functions that
  take the world (they read `WorldState` internals, the convention its class doc states);
  this lambda is the only way a handler or the router reaches them, so the rules stay in one
  file and nothing outside `WorldState` holds the world;
- bound `WorldState` methods: `_drop_carried_haul_item`, `_finish_job`,
  `_resolve_giver_association`, `_resolve_refused_reservations`, `_terminate_haul_job_by_id`,
  `_find_colonist`;
- a lambda for `IncidentScheduler.force_spawn()`, because `_build_dimension_services()`
  (called again by `StateCodec.decode()`) rebuilds `_incidents`.

Handler constructors: `OrderHandler(clock, event_log, scheduler, progress_table,
construction, area_orders, tile_grid, check, drop_carried_haul_item, finish_job,
resolve_giver_association, resolve_refused_reservations)`, `ConstructionHandler(event_log,
construction, object_table, check)`, `ZoneHandler(event_log, scheduler, zone_table, check,
terminate_haul_job_by_id)`, `ActorHandler(event_log, check, find_colonist)`,
`IncidentHandler(clock, event_log, trade, check, force_spawn)`; `CommandRouter(clock,
event_log, construction_system, check, orders, construction, zones, actors, incidents)`.

## Known limitations

- **Two pre-existing bugs found by the fuzzer, not fixed here** (no behaviour change in an
  `R*` task; both reproduce on the pristine `origin/main` copy):
  1. **`cancel_job` with a non-String `job_id` raises a script error.**
     `apply({"type": "cancel_job", "payload": {"job_id": 5}, ...})` reaches
     `String(payload.get("job_id", ""))` in the site-id lookup (`main`:
     `WorldState._apply_cancel_job_command()`; now `OrderHandler.apply_cancel_job_command()`,
     same line) and Godot reports `Invalid call. Nonexistent 'String' constructor.` before
     `apply_job_command()`'s own `invalid_payload` check can reject it. `complete_job` /
     `fail_job` / `invalidate_job` reject the same payload correctly. The probe skips this
     one case so both sides run clean. Suggested fix (a separate `B*` task): check
     `typeof(payload.get("job_id")) == TYPE_STRING` before the site lookup.
  2. **`SaveIO.write_atomic()` refuses the fuzzer's saves** with
     `no_migration_available: missing entity field 'hands'` (first save, tick 100). The
     scenario spawns incidents (`trader_visit`, `wolf_attack` and random ones including
     `migrant_joins`) and sets factions; which entity lacks `hands` was not narrowed down.
     It is a persistence issue (B5's area, not touched here per the owner's note); it is
     not B5's "invalid tile coordinates" refusal.
- **`_init` grew to 132 lines** (the router's 9-line construction). There is no per-function
  cap before R12; R12 has to bring it under 80.
- **`CommandChecks` still takes `WorldState`.** It is an existing static module whose
  contract is to read `WorldState` internals; R10 keeps that and routes it through one
  Callable so that no new module holds the world. Giving each rule explicit dependencies
  would be a rewrite of `command_checks.gd`, outside a move.
- **Stale references outside the owned paths** (left for R16, like R2–R9): doc comments in
  `objects/construction_system.gd`, `scheduling/global_assignment.gd`, the viewer
  (`colonist_panel.gd`, `map_view.gd`, `order_input.gd`), 12 test files (comments, plus one
  assertion message in `test_faction_reservations.gd`), `docs/architecture/orders-and-movement.md`
  and ADRs 014, 023, 025, 028, 030, 032, 035, 036, 039, 040 and 042
  still name `_apply_*_command()`, `_validate_command()` or `_check_place_object_command()`.
  The behaviour they describe is unchanged.
- `BACKLOG.md`'s R4–R9 rows still say `review` although they merged; those rows are not
  R10's, so they were left alone.
