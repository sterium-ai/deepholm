### Deliberate differences (no behaviour change, but not a pure move)

- **Viewer purity rule.** `test_architecture_rules.gd` only allows `scripts/viewer/*.gd` to call
  `get_*`, `apply`, `tick` and `get_events` on a world. `boot.gd` is outside that folder, so
  moving its other calls into `viewer/` failed the rule on the first run. No test was changed
  and nothing was renamed to dodge the regex. Instead, the calls the rule forbids stay in
  `boot.gd`, or `boot.gd` passes them in as a `Callable`, as it already did for
  `map_view.gd`'s `preview_validity`:
  - `world.enable_incidents()` stays in `boot.build_default_world()` (same position: after
    `WorldState.new`, before the starting items), and in `boot._adopt_loaded()` for a decoded
    save (same position: after decode, before `_replace_world`).
  - `world.preview` is passed into `OrderInput.preview_validity()`.
  - `world.spawn_ground_tool_item` is passed into `NewGameSetup.spawn_starting_items()`.
    The regex would not have caught that call (the variable is `new_world`), but it is the
    same kind of call, so it is passed in too.
- **Test-facing names kept.** No test changed. Members that tests read now live in a module,
  and `boot.gd` exposes them as read-only properties under the old names: `_selected_tool`,
  `_tool_buttons`, `_wall_kind_buttons` (`OrderInput`); `_seed_input`, `_active_seed_label`
  (`ControlBar`); `_ui_content`, `_status_label`, `_work_table_panel` (`InfoPanel`).
  `Tool` is `const Tool = OrderInputType.Tool`, and `DEFAULT_BOOT_SEED` is unchanged.
  `_controls` is a `ControlBar` (an `HFlowContainer`) and `_ui_scroll` is an `InfoPanel` (a
  `ScrollContainer`). Child order and node types are unchanged, as the screenshot shows.
- Internal members that no test touches moved without a property: `_wall_kind`,
  `_rotate_build_button`, `_inspected_tile`, `_has_inspected_tile` (to `OrderInput`),
  `_pending_new_game_seed` (to `NewGameDialog.pending_seed`), and `_colonist_panel` (to
  `InfoPanel`).
- `spawn_incident()` now computes the incident's display name even when there is no status
  label. That is a pure text lookup.

## Review round 1 (Codex, `REQUEST_CHANGES`)

Both blocking findings were taken to the owner; no code changed in this round.

- **Blocking: "New modules receive `WorldState` directly" (no-back-reference rule).** The
  owner granted an R13 exception and clarified the rule in `docs/orca/REVIEW.md` on
  `origin/main`, commit `b8fd9e8` ("REVIEW.md: the no-back-reference rule is for core
  modules, not the viewer"), which this branch is now rebased on. The rule now reads: "A new
  module under `game/scripts/core/` never stores or receives `WorldState` [...] Viewer
  modules (`game/scripts/viewer/`, `boot.gd`) are the other side of the
  simulation/presentation boundary and may hold the `WorldState` reference they read from
  and send commands to." The owner's words: viewer modules "pueden recibir `WorldState`
  (leen por getters y envían `apply`/`tick`), como ya hacen todos los scripts de viewer en
  main". Code unchanged, as the owner asked.

## Known limitations

- **Interaction coverage.** No one has clicked through Save/Load/New Game or dragged a tool
  by hand on this branch (see *Review round 1*). Those paths are exercised by the existing
  interaction tests, which drive the real buttons and handlers: `test_order_input`,
  `test_boot_active_seed_label`, `test_river_seed_viewer_interaction`, `test_map_camera`,
  `test_map_pc_playtest_flow`, `test_work_table_panel` and `test_incidents`.
- **One test failed once, then passed.** In the first full run on the branch,
  `test_boot_active_seed_label` failed once ("Load must restore the saved seed 42 world").
  At that moment the author was running a second Godot import of the project in parallel,
  which shares `user://`. The test passed 4 times in isolation and in the clean full run
  above. This is reported, not explained away; if it fails again on a quiet machine, it
  deserves its own task.
- `OrderInput.build_kind_is_rotatable()` and `ControlBar.make_incident_buttons()` still read
  `world._content.list(...)`, a private field, exactly as `boot.gd` did. `debug_scenario.gd`
  already does the same in `viewer/`. A public content getter on `WorldState` would be a
  core change, which is out of scope here.
- `godot --import` still rewrites 31 `game/assets/generated/**/*.png.import` files (line
  endings only). That is task R0b. Those files are not part of this commit.
