> **In short:** Docs only. ADR 044 (*accepted*: the owner signed it off on 2026-10-27) chooses `Vector3i(x, y, layer)` as the one
> tile coordinate and one flat integer index (`z * width * height + y * width + x`, owned by
> `TileGrid`) as the storage key. Layer 0 keeps today's indices, neighbour order and saved
> tile array. Layers connect only through vertical links (stairs, ramps, tunnel). The ADR

> single-layer), commands, events and the viewer, and lists what must change with counts
> measured on `main`. `map-experience.md` gains the viewer's "active layer" contract, and the
> F4 entry in `BACKLOG.md` now cites the ADR. No code changed.

## Decision in one screen

1. **Coordinate:** `Vector3i`, `z` = layer, 0 = surface, increasing downward. All layers have
   the world's `width × height`. `Vector2i` remains only for genuinely planar values
   (directions, footprint offsets, atlas coordinates).
2. **Storage:** one flat index, `z` outermost, owned by `TileGrid` (`index_of`, `coord_of`,
   `in_bounds`, and the three same-layer distance helpers `manhattan`, `chebyshev`,
   `distance_sq`, each keeping today's formula). All per-tile keys become that integer; the four String
   formats are retired. The job-scoped `rescue` progress key keeps its job id, so it becomes
   (job id, tile index) and not the tile alone (ADR 032). Layers can be appended during
   play without renumbering. The deterministic neighbour order becomes ascending flat
   index, which is exactly today's row-major order on one layer.
3. **Between layers:** vertical links only (same `x, y`, `z ± 1`), declared in content
   (`link_down`/`link_up`), derived like regions (no save field). This keeps A8's A\*
   heuristic admissible.
4. **Regions** per layer, joined by a region graph over links. The graph's component labels
   are invalidated by any link change *and* any planar split or merge, and rebuilt on the
   next query. `reachable()` keeps the adjacent-work exception for impassable targets,
   using same-layer neighbours only; **rooms** never span layers;
   **work adjacency** stays planar; **planar distance** is defined only on one layer;
   **incidents** stay on the surface.
5. **Saves:** `{x, y, z}` everywhere, `map.layerCount`, `tiles` stays one flat array (so a
   single-layer save's array is already layer 0). Migration: `layerCount = 1`, `z: 0` on
   every coordinate, tiles unchanged, with a fixture test. Discovered layers are persisted,
   generated from a stream salted by seed and layer.
6. **Commands:** `z` defaults to 0 only at the command boundary; out of range is the existing
   `invalid_target`.
7. **Viewer:** one active layer, never persisted; detailed in `map-experience.md`.
8. **Work order:** A2 → L1 (one index owner, no save change) → L2 (`Vector3i` sweep, save
   bump, migration) → L3 (links, region graph, routing) → L4 (viewer) → F4 gameplay. The
   L-steps are proposed in the ADR; they are not added to the backlog here (outside the
   owned paths). The owner can add them now that the ADR is signed off.
