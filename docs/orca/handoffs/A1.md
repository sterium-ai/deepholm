> writes `docs/architecture/bench-baseline.md`. The header gives the commit, the host, the run
> time and how many other Godot processes were running. Then each benchmark gets a section

> after A0. The owner approved that as a scope amendment on 2026-10-27 (see "Scope amendment"

## Scope amendment: `profiled_tick()` was stale

Approved by the owner on 2026-10-27 ("repair bench calls broken by R6"), recorded in the A1
entry of `docs/orca/BACKLOG.md`.

R6 (`d8c0888`, merged after A0) moved `_rescue_candidates()`, `_trapped_rescue_victims()` and
`_activate_pending_escapes()` from `WorldState` to `TrenchSystem` (`world._trench`).
`BenchCommon.profiled_tick()`, A0's phase-timed copy of `WorldState.tick()`, still called the
old names. A GDScript runtime error aborts only the current function, so every profiled tick
stopped at `rescue_giver`. The first full run showed the effect:

- `bench_tick_scaling` exited 1 (`hash_match=false`);
- `bench_long_session` exited **0** and printed numbers for half-ticks (wall time 55 s
  instead of A0's 163 s).

Fix (`e4bb186`): the same calls now go through `world._trench`, in the same order as
`WorldState.tick()` (`world_state.gd:494`; compared line by line, again after the R7 rebase).
Every other private `WorldState` member the benchmarks use still exists. This keeps what the
benchmarks measure; it restores the measurement. To stop the problem from passing silently
again, the runner fails any benchmark whose output contains `SCRIPT ERROR`. If the error hits
`_init()` itself, `quit()` is never reached and Godot idles forever, so the runner also has a
timeout.

## Acceptance

- **The runner reproduces the A0 lines on the host.** `docs/orca/handoffs/A1-compare-a0.py`
  compares `A0-bench-results.txt` with the raw lines of the baseline run. It matches each
  A0 line by its shape (every number masked, phase lists cut off), in order, and then
  requires every non-timing value to be equal, including the counts before a phase list:

  ```text
  compare-a0: 96 of 96 A0 lines matched by shape, 0 mismatch(es), 0 new line(s) without an A0 counterpart
  ```

  It reports 7 values as `expected`, each with its reason:
  - `busy actors=1000`: `n=19` → `n=23`, `active=528` → `582`, `events=3076` → `3188`. The
    run stops after `RUN_BUDGET_USEC` (90 s) of measured ticks. This host ran faster than A0's,
    so 23 ticks fit, and the job state after 23 ticks differs. `hash_match=true`.
  - leak check: Object count `before=1785/after=1881/delta=96` → `1817/1925/108`. These counts
    depend on the code: A0 ran on `052d8c4`, and R4–R7 have added core modules since (the
    counts rose again with R7: the previous baseline on R6 gave `1809/1914/105`). This is my
    explanation; I did not bisect it. The leak itself (A0's finding) is still there.

  The comparison catches changed counts on phase-list lines. Planting `queue_jobs=9999` in a
  retention line and `n=49` in a backlog line of a copy of the baseline gives
  `DIFF queue_jobs: A0=149 now=9999`, `DIFF n: A0=50 now=49`, `2 mismatch(es)` and exit 1. The
  real baseline gives exit 0.

  Everything else that is not a timing is identical: route statuses, path lengths,
  expansions, resume calls and snapshot sizes; content bytes and counts; save file sizes and
  section sizes; `hash_match=true` on all 15 lines that carry it (as in A0);
  and every retention and backlog queue/event/dirty-cell count in `bench_long_session`.
  Some headline lines (baseline vs `A0-bench-results.txt`):

  | line | A0 | baseline |
  | --- | ---: | ---: |
  | `needs actors=100` first tick, `need_giver` | 153395.33 ms | 110392.25 ms |
  | `busy actors=1000` real tick mean | 4544.30 ms (n=19) | 3818.83 ms (n=23) |
  | `idle actors=1000` real tick mean | 1878.69 ms | 1498.35 ms |
  | `backlog open_orders=2000` tick mean | 234.77 ms | 169.63 ms |

  | save `actors=1000` total save / load | 1976.1 / 2097.7 ms | 1523.9 / 1648.6 ms |

## Known limitations

- Timings depend on the host and on load. The baseline header records how many other Godot
  processes were running, but nothing in the runner keeps the host quiet. Before/after pairs
  must come from the same host, run close together.
- `profiled_tick()` is still a copy of `WorldState.tick()`. The next refactor that moves a
  tick phase must update it. The runner catches a call to a missing method, and the
  `bench_tick_scaling` hash check catches a skipped phase, but neither fixes it.
- `needs actors=100` still measures only its first tick (`n=0`): that tick alone exceeds the
  90 s run budget. This is unchanged from A0 and is a fact the benchmark exists to show.
- Tables use the union of each table's columns, so phase tables have empty cells where a
  phase was under the 0.05 ms print threshold.
- The runner is PowerShell only. There is no bash twin, because no CI gate is wanted.
