# A5 handoff — Job storage: id index, retired jobs, read-only views

> **In short:** `JobQueue` now keeps only open jobs. A finished job moves to a history of
> the last 256 finished jobs that the viewer can still read but that is never saved or
> hashed, so saves stop carrying finished jobs (schema v2, with a v1 → v2 migration and
> fixture). Core code that only reads jobs or colonists gets the live records instead of
> deep copies. ADR 053 records the decisions.

## What changed

1. **Live list and index** (`jobs/job_queue.gd`, `jobs/job_index.gd`). `_finish()` emits
   the terminal event, then `JobIndex.remove()` drops the job from the id, kind,
   reservation-watch and labour indexes and hands it to the history. The list and the
   per-kind lists are compacted in place once removed jobs outnumber half of the list
   (amortized O(1) per removal; a mass cancel is not O(N²)). Index positions became
   submission ordinals so compaction needs no renumbering. `restore()` retires any
   terminal job it is given.
2. **Bounded history** (`jobs/job_history.gd`, new). Last `LIMIT = 256` retirements.
   `get_job()`, `get_jobs()`, `get_jobs_of_kinds()` and `check_terminal()` still see a
   retained job; an evicted one reads as unknown. `get_jobs(false)` lists live jobs only.
3. **Save schema v2** (`persistence/state_codec.gd`, `persistence/save_migrations.gd`).
   `encode()` writes live jobs only; `state_hash()` hashes live jobs only
   (`WorldState.get_jobs([], false)`). `SCHEMA_VERSION` 1 → 2; migration step 1 drops
   completed/failed/cancelled entries from `jobs`. The `jobs` entry shape is unchanged.
4. **Read-only views.** `JobQueue.view_job()` / `view_jobs_of_kinds()` and
   `WorldState._worker_view()` replace deep copies in: `HaulGiver` and `ConstructionGiver`
   (wiring in `world_state.gd`), `ConstructionSystem` (`active_site_fetch_job_ids()`,
   `resolve_freshly_activated_site_fetch_sources()`, `_pending_site_fetch_jobs()`,
   `_site_fetch_work_busy()`, `cancel_construction_site()`, `release_site_builder()`),
   `GlobalAssignment.tick()` (roster is a shallow copy; the post-selection status read is a
   view), `TickPipeline._advance_colonists()`, the tool toils and `CalendarAlertGiver`
   (`_worker_view` instead of `get_colonists`), and `WorldState`'s two job loops. The public
   getters the viewer uses (`get_jobs()`, `get_job()`, `get_colonists()`) still return copies.
5. **`_emit()`** already appended in order since B1 (`job_event_log.gd`); unchanged.
6. To stay inside `job_queue.gd`'s 790-line cap, the four identical reachability blocks in
   the activation paths became one helper, `_blocked_unreachable()` (same checks, same
   order, same block reasons).
7. **`StateCodec._restore_reroutes()`** (found by `test_tool_items`, see below). A job
   finished by a command keeps its id on its colonist's route until the next tick's
   `_advance_colonists()` drops the route (the job has no assignment any more). A save
   taken in that window no longer holds the job, and `_restore_reroutes()` read it
   (`job["kind"]`/`job["target"]` on `{}`: SCRIPT ERROR). It now rebuilds that search with
   plain passability; the cost is never consulted because the route is dropped before any
   resume. The test saves in exactly that window and stays hash-identical tick by tick for
   300 ticks against the uninterrupted run.

## Contract impact

- **ADR 053** (new): live list, history size 256 and why, never saved/hashed, schema v2,
  read-only view rule.
- **Save format:** `schemaVersion` 2. Field names, nesting and value formats unchanged;
  `jobs` now lists open jobs only. Migration `SaveMigrations._v1_to_v2()`; fixture
  `game/scripts/tests/fixtures/save_schema_v2_fixture.json`. The v1 fixture is kept and
  migrates to the v2 fixture exactly (tested).
- **`game-state.schema.json`:** `schemaVersion` const 2, title/description. The v2 fixture's
  state validates with 0 errors (Python `jsonschema` 4.23.0, Draft 2020-12); the v1
  fixture's only error is `2 was expected`.
- **`state_hash()`:** the `jobs` entry now covers live jobs only (terminal jobs left the
  hash with the save). No other hashed field changed; the history is deliberately unhashed.
  For the R14 session both builds print `hash=1180613310` (no terminal job at tick 150).
  `test_toils_dig_chop_regression.gd` pins two hash literals, which moved
  (2864118119 → 1312885732, 698856797 → 4178825690). Evidence that only the hash shape
  changed, not stepping: with the old entry (`"jobs": get_jobs()`, history included; this
  run retires fewer than 256 jobs) temporarily put back in `world_state.gd`, the branch
  passed the test against the **old** literals. The test's header lists shape changes
  as the case for recapturing them.
- **Behaviour visible to commands:** a cancel/complete naming a job finished before a load,
  or evicted from the history, is rejected as `unknown_job` instead of
  `job_already_terminal` (ADR 053, Consequences).
- `save-system.md` ("Jobs" paragraph, migration chain), `jobs/README.md` (history, views).

## Known limitations

- The views are the live records. A caller that mutated one would mutate the simulation;
  the rule is in ADR 053 and `jobs/README.md`, not enforced by the type system.
- Core readers outside the owned paths still deep-copy (`combat_system.gd`,
  `zone_handler.gd`, `work_progress.gd`, `needs_system.gd`, `trench_system.gd`, the
  `_get_job` callables injected into toils and givers). They are correct as they are and
  now copy only live jobs plus at most 256 retained ones; converting them is a follow-up.
- `world_state.gd` is exactly at the 800-line rule; the next change there needs room first.
- `tools\check_core_warnings.ps1` reports one warning below the baseline; I left
  `warnings-baseline.txt` alone (outside the owned paths).
- A job's id can outlive its record for one tick on a colonist's route or work (item 7).
  `_restore_reroutes()` is the only reader that met that case in the suite. Any future
  reader of a route's job across a load must tolerate `{}` the same way.
