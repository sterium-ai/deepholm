# A15 handoff: localisation-ready text

> **In short:** The core no longer returns English. A rejected command now carries its
> unchanged `reason` plus `params`, which holds only codes and values: `"detail"` names the
> failed rule, `"remedy"` is a JobQueue remedy, and any other key is a named value. This
> replaces `message`. The 68 old sentences are now 60 `rejection.<detail>` entries (some were duplicates) in
> `data/text/en.json`, word for word except one capitalisation (see "Review round 2"), with
> `{name}` placeholders. `TextTable` loads
> `data/text/<locale>.json` on top of `en.json`, and any key the locale lacks falls back to
> English. Every visible string in `viewer/*.gd` and `boot.gd` is now a key. Tile and calendar
> labels are keys too. Two new tests enforce this. `test_viewer_text_lint.gd` fails on a
> player-facing literal. `test_text_pseudo_locale.gd` builds a pseudo locale and proves that
> every key the game can ask for resolves. It also sends 12 real bad commands through
> `apply()` and renders their rejections. [ADR 052](../../decisions/052-localisation-ready-text.md)
> records the decision. Save format and `state_hash()` are unchanged.

> changes only docs and the warnings baseline): `run_tests: all 108 test(s) PASS  [642s]`
> **Review round 1** (`.orca-review.md`, REQUEST_CHANGES): the one blocking finding (no suite

## Contract impact

- **Rejection shape (public, ADR 052):** `rejection.message` → `rejection.params`. Reason codes
  are unchanged. Every `"reason": "..."` literal in the core is the same set as on `main`
  (`git diff origin/main -- game/scripts/core | grep '"reason"'` shows only the same reasons,
  moved next to `params`). The `command_rejected` event already carried only `{reason}`.
- **Save format: unchanged.** Rejections are return values. Events are not a save field
  (`SaveIO.TOP_LEVEL_FIELDS`), and `calendarAlerts` persists only fired window ids
  (`GiverCodec._encode_calendar_alerts`). No schema bump, migration or fixture is needed.
- **`state_hash()`: unchanged.** No hashed field changed. The determinism, save and replay
  tests pass with their existing golden hashes.
- **Content:** `tiles.json`/`calendar.json` label values changed, but not their shapes. The
  manifest version is unchanged (it is a version string, not a hash).

## How the two acceptance tests work

- **Lint (`test_viewer_text_lint.gd`).** It scans every string literal in `viewer/*.gd` and
  `boot.gd`. Comments, `print`/`push_error`/`push_warning`/`printerr`/`assert` lines and lines
  marked `# dev-text` are skipped. After format specifiers and escapes are removed, a literal is
  player text if it has two words separated by a space or starts with a capitalised word. Keys,
  ids built with `"%s_%d"`, node and field names (`factionId`) and compass codes (`NE`) are not.
  The test first lints a planted source and must flag exactly its three player literals while
  skipping the exempt ones. Only the two `read_file` lines in `command_recorder.gd` carry
  `# dev-text`.
- **Pseudo locale (`test_text_pseudo_locale.gd`).** It writes `en.json` and a `qps.json` into
  `user://`. In `qps.json` letters are accented and the text is bracketed `[!! … !!]`, while
  placeholders are kept and one key is left out. It loads that locale with
  `TextTable.new("qps", dir)` and checks three things: every key resolves to its pseudo text with
  English's placeholders, the dropped key falls back to English, and a locale with no file falls
  back to English. It then counts the keys the game can ask for, 256 at present (255 before the rebase onto A14) (it prints the
  count and fails below 150), and requires each to exist in `en.json` and resolve through the pseudo locale. The keys
  come from:
  - key literals in the viewer;
  - tile and calendar labels, read from the session `ContentRegistry` (`Boot.session_content()`,
    A13);
  - the per-kind families: `status.job.<jobs.json kind>`, `status.need.<needs.json kind>`,
    `incident.<id>`, `work_table.labour.<LABOUR_KINDS>`, `controls.tool_<TOOL_KEYS>`,
    `status.toil.<ToilExecutor.VOCABULARY>` minus `reserve`/`release_all`, colonist-panel
    reason→remedy tables, and `save.reason.<code>` for every SaveIO/SaveMigrations code;
  - every `detail`, `reason`, `remedy`, `BLOCKED_*` and `block(job, …, "<remedy>")` literal in
    the core sources. Each census pattern must match at least once.

  Finally it sends 12 bad commands through `WorldState.apply()`: chop, dig, place_object,
  set_faction, set_labour, spawn_incident, zone_remove, cancel_job, accept_trade, area_order,
  an unknown type and a stale tick. Each must carry no `message`, and `rejection_text()` must
  render it with no `{…}` left. The stale tick must render exactly "Command tick N does not
  match current tick M."

## Known limitations

- Only `en.json` ships. Translations, fonts and RTL are non-goals.
- Item, object, faction and actor **ids** still appear raw inside some lines: the held-tool
  kind, hands, trade offers and the incident alert's faction. They are data, not literals, so
  the lint does not cover them. Display names for those kinds would be a content task.
- Developer diagnostics keep English next to a `code`: SaveIO/ContentRegistry/ReplayLog
  messages and `command_recorder.read_file`. The player sees save failures through
  `save.reason.*`/`save.write_reason.*`.
- Godot's own dialog buttons (`ConfirmationDialog` OK/Cancel) use the engine's built-in text.
- `test_viewer_text_lint` is a heuristic. A one-word, all-lowercase literal shown to the player
  (for example `"x1"`) is not flagged; the existing ones are already keys.
- The locale is the OS language or `--locale=<code>`. There is no in-game switch.
- `TextTable.requested_locale()` reads `OS` in the viewer only; the core is untouched.
