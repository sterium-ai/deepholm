# L1 handoff: `TileGrid` as the only index owner

> **In short:** Every flat tile index and every planar distance in `game/scripts/core` now goes
> through `TileGrid` (ADR 045 §2 and §4, step 2). The three distance formulas stay three
> separate helpers. Behaviour, the save format and `state_hash()` do not change. The A2, A14,
> A16 and R10 scenario dumps are byte-identical to `main`.
>
> - The suite is green: `run_tests: all 128 test(s) PASS  [698s]` (`main`: `run_tests: all 127 test(s) PASS  [703s]`).
> - The only new test is `test_tile_grid_helpers.gd`.
> - Coordinates stay `Vector2i`. `Vector3i` and the `a.z == b.z` assert are L2's job (the
>   entry's non-goal).

## What changed

### `core/map/tile_grid.gd` (the owner)

| Helper | Formula | Who calls it |
| --- | --- | --- |
| `static flat_index(x, y, grid_width)` | `y * grid_width + x` | the only index formula in the core; for callers that hold a width, not a grid |
| `static flat_coord(index, grid_width)` | `Vector2i(index % grid_width, index / grid_width)` | its inverse |
| `index_of(tile: Vector2i)` / `coord_of(index)` | `flat_index`/`flat_coord` with the grid's own `width` | the ADR's names, on an instance |
| `tile_index(x, y)` | `flat_index(x, y, width)` | kept: the many `(x, y)` int callers (`object_table`, `toil_bindings`, `test_access`, tests) |
| `static manhattan(a, b)` | `absi(dx) + absi(dy)` | nearest-candidate ranking, travel penalty, A\* heuristic |
| `static chebyshev(a, b)` | `maxi(absi(dx), absi(dy))` | the `<= 1` "next to" test and square rings |
| `static distance_sq(a, b)` | `dx * dx + dy * dy` | flee-candidate comparison |

- `tile_at(index)` was renamed `coord_of(index)`; its only callers were 2 lines in
  `object_table.gd`.
- `in_bounds(x, y)` is unchanged. GDScript has no overloads, and L2 changes the signature to
  `Vector3i` anyway.
- The class invariant now reads `tiles[tile_index(x, y)]` instead of restating the formula.

## Known limitations

- **Helpers take `Vector2i`.** ADR 045 §4 has them take `Vector3i` and assert `a.z == b.z`.
  That signature belongs to the L2 sweep (`Vector3i` is this entry's non-goal), so today they
  are planar and have no `z` to check.
- **Small hot-path call cost.** The index and heuristic are now a static call instead of
  inline arithmetic: `RouteSearch._frontier_push()`, `Passability.is_passable()`, and the
  regions/rooms flood fills. No benchmark was run; `run_benches` is not a gate. If A8's route
  bench moves noticeably, these are the lines to look at.
- **Two ratchets outside the owned paths, left alone:**
  - `docs/architecture/warnings-baseline.txt` could be lowered by 11
    (`check_core_warnings` says so);
  - `world_generator.gd`'s frozen cap in `core-budgets.json` (870) could drop to 860.

  Neither file is an owned path, so the owner decides.
- Neighbour steps inside `regions.gd` `_step()` (`index ± _width`, `index ± 1`) stay stride
  arithmetic on an index, not coordinate→index math. L3's link edges change that function
  anyway.
