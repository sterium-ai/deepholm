## What changed

### `core/map/tile_grid.gd` (the owner)

| Helper | Formula | Who calls it |
| --- | --- | --- |
| `static flat_index(x, y, grid_width)` | `y * grid_width + x` | the only index formula in the core; for callers that hold a width, not a grid |
| `static flat_coord(index, grid_width)` | `Vector2i(index % grid_width, index / grid_width)` | its inverse |
| `index_of(tile: Vector2i)` / `coord_of(index)` | `flat_index`/`flat_coord` with the grid's own `width` | the ADR's names, on an instance |
| `tile_index(x, y)` | `flat_index(x, y, width)` | kept for the many `(x, y)` int callers |
| `static manhattan(a, b)` | `absi(dx) + absi(dy)` | nearest-candidate ranking, travel penalty, A\* heuristic |
| `static chebyshev(a, b)` | `maxi(absi(dx), absi(dy))` | the `<= 1` "next to" test and square rings |
| `static distance_sq(a, b)` | `dx * dx + dy * dy` | flee candidates, grove radius |
| `static coord_key(x, y)` / `coord_of_key(key)` | `"x_y"` and its parse | objects, ground berries, work progress, combat target keys, the save/hash boundary |
| `static target_key(x, y)` | `"tile:x,y"` (`TARGET_KEY_PREFIX`) | work and build target reservations |
| `static cell_key(x, y)` | `"cell:x,y"` (`CELL_KEY_PREFIX`) | haul destination cell reservations |
| `static comma_key(x, y)` | `"x,y"` | construction site keys; the tile part of an area order's expanded `command_id` |

- `tile_at(index)` was renamed `coord_of(index)`. Its only callers were 2 lines in
  `object_table.gd`.
- `JobQueue.TARGET_KEY_PREFIX` moved to `TileGrid`. Its only users were `job_queue.gd` and
  `construction_system.gd`, which now call `target_key()`.
- `in_bounds(x, y)` is unchanged. GDScript has no overloads, and L2 changes the signature to
  `Vector3i` anyway.

## Known limitations

- **Helpers take `Vector2i`.** ADR 045 §4 has them take `Vector3i` and assert `a.z == b.z`.
  That signature belongs to the L2 sweep (`Vector3i` is this entry's non-goal).
- **String keys are centralised, not retired.** ADR 045 §2 wants int keys eventually. Their
  formats are in saves, events and replays, so retiring them is a save change for a later
  task (L2's bump is the natural place). After this change it touches only `TileGrid`'s key
  helpers and their decoders.
- **Small hot-path call cost.** The index and heuristic are now a static call instead of
  inline arithmetic:
  - `RouteSearch._frontier_push()`;
  - `Passability.is_passable()`;
  - the regions/rooms flood fills.

  No benchmark was run; `run_benches` is not a gate.
- **Two ratchets outside the owned paths, left alone:**
  - `docs/architecture/warnings-baseline.txt` could be lowered by 11;
  - `world_generator.gd`'s frozen cap in `core-budgets.json` (870) could drop to 860.

  The owner decides.
- The neighbour steps in `regions.gd` `_step()` (`index ± _width`, `index ± 1`) stay
  stride arithmetic on an index, not coordinate→index math. L3 rewrites that function for
  link edges.
