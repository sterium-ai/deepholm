# A16 handoff: scenarios as content

> **In short:** How a new world is set up now lives in `game/content/scenarios.json`
> (schema `scenarios.schema.json`), and `game/scripts/core/world/scenario_builder.gd` builds
> a world from one entry.
>
> - The default New Game is the `new_game` entry. The old `debug_scenario.gd` is now the
>   `debug` entry, and the script only wraps it.
> - The New Game dialog lets the player pick a scenario and keeps that scenario's tick rate.
> - Both scenarios build headless with a deterministic `state_hash()`.
> - The default New Game and every debug-scenario build are byte-identical to `main` for six
>   cases: saved state, event log and 100 ticks of hashes.
> - ADR 053 records the decision. Review round 1 is addressed (below). The owner approved
>   deferring the roster, calendar and incident list to the new task A16b.

### How the old code maps to steps

| Old | New |
| --- | --- |
| `build_default_world()`: `WorldState.new(seed, 10, mapgen size, false, content)` + `enable_incidents()` | `new_game` entry: no `map` (mapgen default size), `tick_rate: 10`, `incidents_enabled: true` (the builder constructs with `false`, then calls `enable_incidents()`; on a fresh world this is the same as the constructor flag, because `reserve_actor_ordinal_above()` finds no incident actors). |
| `NewGameSetup._spawn_starting_tools()` / `_needed_tool_kinds()` / `_claim_starting_tiles()` / `_fallback_anchor()` | `needed_tools` step: the same helpers, with `world.spawn_ground_tool_item()` in place of the callable. Pool tiles from the cursor on, which is 0 for `new_game`. |
| `NewGameSetup._spawn_starting_beds()`: pool slice from `tool_count` | `per_colonist_objects` step with `kind: "bed"`: a pool slice from the cursor, which equals `tool_count` after `needed_tools`. The command id `"starting_%s_%d" % [kind, i]` gives the same `starting_bed_<i>`. |
| `DebugScenario.build()`: `WorldState.new(seed, rate, 48, 48, incidents)` | `debug` entry: `map: {48, 48}`, `seed: 20260915`, `tick_rate: 10`. `incidents_enabled` comes from options (tests: `false`; Debug button: `true`). |
| `_place_scenario_objects()`: offset 173; wall row (6, one door) at `clamp(top + height)`; furniture (3 chairs, 2 tables) at `clamp(top − 2)`; forage (1 berry bush, 1 bed) at `clamp(wall_row + 2)` | `object_rows` step: `seed_offset: 173`, rows `wall`/`furniture`/`forage` with anchors `clearing_bottom+0`, `clearing_top−2`, `clearing_bottom+2`. `clamp(clamp(b)+2)` equals `clamp(b+2)` because `b ≥ 0`. The command ids `scenario_object_<row>_<i>` are unchanged. |
| `_submit_dig_orders()`: 24 orders, offset 91, priority 1, excludes the till target | `dig_orders` step: `count: 24, seed_offset: 91, priority: 1`. The till target is excluded only when an active `till_plot` step exists. |
| `if seed_value == SCENARIO_SEED:` farm bootstrap | `"when": "scenario_seed"` on `till_plot` and `ground_items` |
| `_pick_till_target()` + `_till_starting_plot()` (radius 15, budget 800, HIGH priority, needs top-up) | `till_plot` step: `search_radius: 15, tick_budget: 800`. The target is chosen lazily, first by `dig_orders`, which is the same point in the build as before. The needs top-up reads through `ActorTable.get_component(colonist, "needs", content)` (see Validation). |
| `_pick_seed_tile()` + `_seed_starting_farm_stock()` (3 seeds) | `ground_items` step: `kind: "seed", count: 3, search_radius: 15`. It uses the same colonist snapshot and till target. |

## Contract impact

- **New content kind and contracts:**
  - the new kind `scenarios`, with schema `scenarios.schema.json`;
  - ADR 053;
  - the `extension-points.md` "Scenario" section;
  - a `source-of-truth.yaml` entry;
  - the `foundation-audit.md` §3.6 status.
- **`content/manifest.json` version:** **not** bumped. A save's header records it, and
  scenarios are read only while a world is built.
- **Save format:** unchanged. No persisted field, nesting or value format changed, and no
  file under `core/persistence/` changed. The dump shows `to_save_state()` byte-identical.
- **`state_hash()` coverage:** unchanged (`world_state.gd` is not touched).
- **Registry:**
  - `scenarios` is optional, so the minimal fixture bundles the tests write still load.
  - When present it is schema-validated, has duplicate ids rejected, and accepts packs.
  - `_check_scenarios()` requires each step's fields to match `SCENARIO_STEP_FIELDS`, and
    requires `when` to come with the scenario's `seed` (`schema_violation`). Every object and
    item kind a step names, including `door`, must be declared (`dangling_reference`).
- **Core rules:**
  - The builder lives in the core and drives the world as a client. It is not held by
    `WorldState`.
  - The two bootstrap writes the old debug scenario made from the viewer moved here and are
    documented: the needs top-up during `till_plot`, now through the accessor, and the
    item-table write for `ground_items`. Viewer scripts no longer write any private
    `WorldState` field.
  - Only seeded RNGs are used.
- **Deferred with the owner's approval to A16b:** the per-scenario roster, calendar and
  per-incident list.
