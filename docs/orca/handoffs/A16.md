# A16 handoff: scenarios as content

> **In short:** How a new world is set up now lives in `game/content/scenarios.json`
> (schema `scenarios.schema.json`), and `game/scripts/core/world/scenario_builder.gd` builds
> a world from one entry. The default New Game is the `new_game` entry. The old
> `debug_scenario.gd` is now the `debug` entry, and the script only wraps it. The New Game
> dialog lets the player pick a scenario. Both scenarios build headless with a deterministic
> `state_hash()`. The default New Game and every debug-scenario build are byte-identical to
> `main`: saved state, event log and 100 ticks of hashes, for six cases. ADR 052 records the
> decision.

## Contract impact

- **New content kind** `scenarios`, schema `scenarios.schema.json`, and ADR 052.
  `content/manifest.json`'s version is **not** bumped. A save's header records it, and
  scenarios are read only while a world is built, so a bump would only reject existing saves.
- **Save format:** unchanged. No persisted field, nesting or value format changed, and no file
  under `core/persistence/` changed. The dump below shows `to_save_state()` byte-identical.
- **`state_hash()` coverage:** unchanged (`world_state.gd` is not touched).
- **Registry:** `scenarios` is optional, so the minimal fixture bundles the tests write still
  load. When present it is schema-validated, has duplicate ids rejected, accepts packs (a
  pack may add or override a scenario), and is cross-checked by `_check_scenarios()`:
  - each step's fields must match `SCENARIO_STEP_FIELDS`, else `schema_violation`;
  - `when` needs the scenario's `seed`, else `schema_violation`;
  - the object kinds a step names (including `door`) and the `ground_items` item must be
    declared, else `dangling_reference`.
- **Core rules:**
  - The builder lives in the core and drives the world as a client (`apply()`, `tick()`,
    getters, `enable_incidents()`, `spawn_ground_tool_item()`). It is not held by
    `WorldState`.
  - The two bootstrap writes the old debug scenario made from the viewer moved here unchanged
    and are documented on their steps: the needs top-up during `till_plot`, and the item-table
    write for `ground_items`. Viewer scripts no longer write any private `WorldState` field.
  - No global randomness: the builder uses fresh RNGs seeded with `seed + seed_offset`, as
    before.
  - No per-colonist loop outside the toil executor: `till_plot`'s needs top-up is a bootstrap
    loop over the roster that already existed in `debug_scenario.gd`.
- **Not done from the goal's list.** Each needs a construction parameter that does not exist
  yet; see ADR 052, "Consequences":
  - a per-scenario starting roster (`mapgen.json`'s `colonist_count`, mirrored at compile
    time);
  - a per-scenario calendar (`CalendarService` reads `calendar.json`);
  - a per-incident enable list (`IncidentScheduler` is on or off).

  The schema leaves these fields out rather than accepting values it would ignore.
  Scenarios do set the map size, the seed or a generated map, items, objects and the incident
  switch.
